# Smaller items of the candidates list

## Goal

`planning/v1.2-candidates.md` collects small findings that waited for v1.2: six items noted on 2026-10-21 from the acceptances of F0038 (the documents say what is true today), F0039 (the code says what it does once) and F0040 (agent code never runs with the factory's rights); the items the human added on 2026-10-24 and 2026-10-25 for this feature; and what was found on `vm` on 2026-10-26 (the cause of the zero bytes, F0046-S0002's review and F0046-A0001's notes). F0042 (the stage environment behind one interface), F0043 (the machine and the stage image) and F0044 (the layers go) removed much of what the older findings were about; this feature, the fourth and last of v1.2 (`planning/v1.2-plan.md`, section "F0045"), checks each item against the code as F0044 and F0046 (work environment options) left it on `main`, and builds what is left. It is built by the instance `vm` on the VM with the container stage environment. It is for the human, who runs the factory on a VM that costs money while it runs and that must not keep a stale page after a rollback, and for every later reader of the code and the tests. When it is done: a slip the smoke tester finds in a document goes straight to the docs stage; the reset drops the page cache after every rollback, installed by `vm/setup.sh`; the script says exactly how to install a changed unit; the stall reason `left_branch` is gone with the records contract `4.0`; the agent files' folder and the image identity file are required settings, and the settings model refuses what the reading refuses; the process result no longer carries a field no caller reads; the factory can power its VM off after an idle stretch, an option off by default whose one right `vm/setup.sh` gives only when it is used; no test module imports another, and the tests' leftovers of F0044 are cleared. Done when every story below is merged and `make check` is green.

## Decisions taken for the human

1. **The split and the order** (all stories). One story per item that stays, with three exceptions. The idle shutdown is two stories: the factory's part (S0008: the setting, the interface, the wrapper, the counter, the wiring; testable with a manual clock and a stand-in `sudo`) and the machine's part (S0009: the script's option, the right, the environment file's line), because each is a coder's forty minutes and the second is pinned by text tests of F0043-S0003's kind. The two defaults are two stories: the reading (S0005) and the model (S0006), because the model's required field changes some thirty-eight constructions in thirty-three test modules, a tester's run of its own; the model's check of `container_env` (item 3 (d) of the brief) joins S0006, the same model and the same tests. The cache drop is one story with its script step (S0002), because the factory's call and the machine's right must arrive together. S0001 first, so that the stories after it profit from the short way of a slip in a document; S0002 early, because `vm` runs on a fix made by hand; S0010 and S0011 last, so that the guard and the tidy-up hold for every test this feature wrote. Options: A, this (taken); B, the idle shutdown and the settings each as one story (two rule sets and two documents in one coder's run); C, S0010 first (later testers obey the rule from the start, but its import list would be counted on a `main` that later stories still change).
2. **`UV_LINK_MODE=copy` fell with F0043-S0001 and F0044** (no story). The finding (F0040-A0002, note 4a) was that `sudo ... env -i` dropped the image's `UV_LINK_MODE=copy`, so uv printed its hard-link warning into the agent's context. On the container environment the call is `podman run` with `--env` entries for the request's environment only (F0042-S0003, `PodmanRuns`), so the container keeps the stage image's own `ENV`, and `vm/Dockerfile` holds `ENV UV_LINK_MODE=copy` (checked on 2026-10-26); since F0044 no agent runs on the host and the `sudo` chain is gone (F0044-S0005). Nothing is left to change.
3. **`leftovers_command()` without `-B` fell with F0044-S0003** (no story): that story removed `leftovers_command`, its module constant and the program `factory.entry.leftovers` whole.
4. **The "Open" of the entry on the kill under `sudo` fell with F0044-S0005** (no story). The entry "The agent's own `timeout` kills a run under `sudo` at its time limit" (F0012-S0024) ends with "Open: observed for real only at the first start." and is now closed by the line "Replaced by the throwaway container, v1.2 F0044-S0005" (`docs/decisions.md`, checked on 2026-10-26), which ends the open point with the mechanism it was about. Nothing is left to write.
5. **`output_abandoned` goes, the drain stays** (S0007). The field is read by no caller under `src/factory` (F0040-A0002, note 4c; it is accepted as dead code in `security/duplicates-baseline.txt`). Since F0044 the host starts only git, `zfs`, `podman` and, in the suite, `make`, whose pipes close with their process; a field that only tests read is the "said twice" F0039 removed elsewhere. The bounded read after the child's end (`PIPE_DRAIN`) is behaviour and stays exactly as it is. Options: A, the field goes (taken); B, a caller logs it (a line no stop and no operator reads); C, keep it (the baseline keeps a standing finding).
6. **A slip in a document goes from the smoke test straight to `docs`** (S0001; the human's change 1). The long way (F0038-A0001, note 8) was smoke test, then `doing` (the coder may not write `docs/`), then review, then docs, then the smoke test again: four extra runs each in F0038-S0007 and S0009. The decision rules already treat every `next` entry after the first as a rework counted against the stage's `round_cap` (`factory.domain.decisions.decide`), so adding `docs` to the smoke test's `next` needs no code: the smoke tester ends with `docs` when every finding is a slip in a document the documenter writes and the code does what the work item says, else with `doing` as today. The candidates list names "a finding the reviewer marks as docs-only", but no reviewer runs after the smoke test; the smoke tester is the one who sees the finding. Options: A, this (taken); B, the coder passes a docs-only finding on with `review` and the reviewer with `docs` (the long way, shortened by nothing); C, a factory rule that reads the findings' paths (a new mechanism for a judgement an agent already makes).
7. **The rule for the tests' imports: no module imports a test module** (S0010). The candidates list proposes "shared test code lives only in `*_support.py` modules". Shared code also lives in modules named otherwise (`human_clone.py`, `recording_log.py`, `source_search.py`, `shipped_agents.py`, `time_limits.py` and others), and renaming them would change some hundred imports for no gain. So the rule is the one that removes the problem: no module under `tests/` imports a module whose file name begins with `test_`, in any of the three forms; what one test module imports from another moves into a support module, and a new support module is named `*_support.py`. The guard is `tests/test_shared_imports.py`, beside the `tests/test_shared_*.py` that guard the shared helpers today. On 2026-10-26 thirty-nine such import lines exist in thirty-two modules. Options: A, this (taken); B, the `*_support.py` rule of the candidates list, with every shared module renamed.
8. **What idle means** (S0008; the human's open point, decided as proposed). An iteration of the loop is idle when its tick ran, ended at no repository stop, and dispatched the evaluation's `idle` event, `handled`. That holds when nothing can be started, when the first waiting work item waits for the human (an approval, a posted question: the lease is not held then, as the candidates list proposes), and when a claim is held by another instance. It does not hold for a tick that ended at a stop, or that handled any other event (a capped or failing event included): a stop waits for a fix the operator may make on the machine itself, so the machine stays up. An iteration that ran no tick neither counts nor ends the stretch; the machine is powered off only right after an idle tick, when the stretch since the last tick that was not idle (or since the instance started) has lasted at least the limit. Options: A, this (taken); B, every iteration without activity counts, stops included (the machine could power off while the operator fixes a low disk); C, a stage waiting for the human does not count (a story waiting overnight for its merge would keep the VM running all night, which is the cost the option exists to save).
9. **The right is one `sudoers` line for `/usr/bin/systemctl poweroff`, and the wrapper runs `sudo -n /usr/bin/systemctl poweroff`** (S0008, S0009). It is the way F0043's decision 7 gave the `zfs` fallback its rights and S0002 gives the cache drop its own: one file under `/etc/sudoers.d/`, mode `0440`, checked with `visudo -cf`, exactly one command with its argument. The script writes it only with `--idle-shutdown` and removes it on a run without the option, so the right exists exactly while the option is in use; the factory's setting comes from the same run (the environment file's line), so the two cannot drift. Options: A, this (taken); B, a polkit rule for `org.freedesktop.login1.power-off` and a plain `systemctl poweroff` (whether `polkitd` is on Google's Ubuntu image was not checked, and the rule language is JavaScript); C, the factory as root (rejected by the plan).
10. **A failed power-off is a log line, not a stop** (S0008). When the wrapper fails (no right, `sudo` missing, its time limit), the factory logs one line that begins `idle shutdown: ` and names the fault, does not raise, and starts a new stretch, so it tries again only after another full limit. A stop would keep a machine running that the operator meant to save, and stop no work. No preflight item checks the right: the option is off by default, and the log line says what is missing.
11. **The guide describes the start, not a script** (S0008). Starting again is outside the factory: the human runs `gcloud compute instances start factory-vm --zone europe-west3-a`, or sets up by hand a GCP instance schedule that only starts the VM. `docs/operator-guide.md`, `## The machine`, *The idle shutdown*, says both and that a merge, a close or an answer while the VM is off is seen at the first tick after it starts again. The runbook gets no schedule commands (the human's answer, decision 32 (c)).
12. **The option is off by default and needs no switch of the environment** (S0008, S0009). Unset, blank or `0` means off; since F0044 only the container environment exists and the Docker path is gone, so "never on `inline`/Docker" holds by construction; an instance off the VM that sets the option fails to power off (decision 10) and runs on.
13. **`left_branch` goes with the records contract `4.0`** (S0004; F0044's answer 29 (b)). Removing a value of `StallReason` narrows the work item and acceptance states, a change that can break a reader, so the major rises after F0044's `3.0`. On the container environment the agent works on the dataset and cannot move the host's branch, so the check after the agent (the host checkout's branch against the work item's) can never fire and goes with the reason; the stall service still brings the checkout back to the branch before it takes, which S0004 does not touch.
14. **The two defaults become required settings, not the VM's paths** (S0005, S0006; F0044's answer 29 (c)). Both paths belong to the machine: `vm/setup.sh` writes them into the environment file (`FACTORY_IMAGE_ID_FILE=/srv/factory/<instance>/image-id`, `FACTORY_CLAUDE_HOME=/srv/factory/<instance>/factory/claude`), so `vm` is unaffected. A default in `factory.domain.settings` would put one machine's layout into the domain, and a wrong default fails late and quietly (the preflight's `agents` item finds no agents, or the image identity file is missing), while a required setting stops the start with the stop of invalid settings naming the variable. So `read_settings` refuses a missing, blank or relative `FACTORY_CLAUDE_HOME`, and, when it is given a reader of the image identity (`factory-run`, `factory-watch`), a missing, blank or relative `FACTORY_IMAGE_ID_FILE`; `$HOME/.claude`, `/home/agent/.claude` and `/opt/factory/image-id` are never read. The model's field `agent_home` loses its default too, in S0006 (the human's answer, decision 32 (b)). Options: A, required (taken); B, the VM's paths as defaults, built from `FACTORY_INSTANCE` (the domain would know `vm/setup.sh`'s layout, and a machine made otherwise would read a wrong path silently).
15. **The reset drops the page cache after every rollback, through one helper run with `sudo`** (S0002; the brief's item 3 (a)). A page written through `mmap` survives `zfs rollback` in the page cache (reproduced on `vm` on 2026-10-26); `echo 1 > /proc/sys/vm/drop_caches` after the rollback clears it, and only root may write that file. So `ZfsSnapshots.reset()` runs `sudo -n /usr/local/bin/factory-drop-caches` right after a rollback that succeeded, and a fault of it fails the reset as a fault of `zfs` does (loud, and the preflight's agent-run probe meets it before any stage); `vm/setup.sh` writes the root-owned helper (`sync`, then the drop) and one `sudoers` rule for exactly it on every run, since every machine needs it. The command is a constant of the adapter passed by the wiring, not a setting, so no environment file can leave it out. The drop is machine-wide: the next sync reads `.venv` from the disk, which the reset's timing line shows. Options: A, this (taken); B, the script's `zfs` wrapper drops the cache after a rollback, as `zfs-fresh` does on `vm` today (no factory change, but the fix holds only while `FACTORY_ZFS` names the wrapper, which a setting can undo silently); C, unmount and mount the dataset around the rollback (Linux refuses a delegated mount to a user, the plan's first risk, so it needs root as well, and a mount must not change under a running container).
16. **No content check at the sync** (no story). The candidates list also proposes that the sync compares each file with git's hash before the base moves. With the drop of S0002 the fault's cause is gone, and a check would be a second mechanism that finds the damage after it happened and can only refuse the stage. Solid over clever: if a zero-byte or cut file is seen again after S0002, the check becomes a candidate again. Options: A, no check (taken); B, `git update-index --really-refresh` or a hash comparison in the sync script (seconds per stage on a large `.venv`-free checkout, and a new stall or stop reason).
17. **A changed unit: the script keeps its rule and names the operator's own copy** (S0003; the brief's item 3 (b)). Root installs a file from the factory's checkout only in the run that made the clone or when the file is missing (F0043-S0003), because `factory` can write that checkout and a unit decides the user a service runs as. The guide's advice to remove the installed file and run the script again made root install the checkout's text after all, so it goes; instead the operator installs the new `vm/factory.service` or `vm/git-credential-factory` from their own copy of the ref, which the rebuild already copies `vm/setup.sh` from, and the script's two lines say so. Options: A, this (taken); B, the script replaces a different installed file (the simplest for the operator, but root would install a file `factory` may have changed, the boundary F0043 drew); C, the script carries the unit's text itself, as it carries the `sudoers` rules (`vm/factory.service` and its tests would move into the script: a larger change for the same trust).
