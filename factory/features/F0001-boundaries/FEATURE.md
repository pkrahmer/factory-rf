# Boundaries

## Goal

Every outside party is reached through one boundary: the git command-line tool through one wrapper class, the hosting service through an interface with a PyGithub implementation and one fake, the project commands through an interface with a make-based class, and the agent runtime through an interface with a `claude -p` implementation and a fake. Their inputs and outputs are Pydantic DTOs shaped by what the factory needs, not by the tool, and named kill points in the wrappers let later tests inject a crash. The feature is useful on its own: everything that comes after it calls only these interfaces. Done when each of the four boundaries has its first implementation and is callable through its interface, a fake exists for the hosting service and for the agent runtime, the git wrapper is tested against a real local bare remote, each kill point can be armed and is reached by its wrapper, and a search finds no call to an outside tool (git, the hosting service, make, claude) outside the wrappers.

## Scope

- Named kill points: an injection seam, inert unless a test arms it, and the root of the factory's error hierarchy (R36).
- The hosting-service interface (R10) with its DTOs, the marker and the post key; the PyGithub implementation with its one error type (SI2.1, SI2.2); the one fake (SI2.3).
- The git wrapper with DTOs (R9): one place that starts a subprocess, fetch with prune, remote-tracking branches, resolving refs, a file at a commit, files under a directory, ancestry, log, changed paths, status, clone, check out, commit, push with its outcome, delete branches, merge with abort on a conflict, reset and clean, revert paths, move.
- The project-commands interface and the make class (R11), with a generic check result that has no layer names (R8).
- The agent-runtime interface, its DTOs and the fake; the `claude -p` implementation with the budget resume, the `time_limit` and the version query (R12).
- Searches in the tests that prove the boundaries: only one module imports `github`, only one starts a subprocess, only one names `make`, no `dict[str, Any]` crosses a function boundary (R5, R7).

## Out of scope

- The write-path guard hook command and what it refuses: F0004. The guard settings file is only written here.
- Reading agent files from disk and composing the prompt: F0005; the keys an agent file may hold: F0010.
- Scrubbing the agent's environment and running as a second OS user: F0010. The runtime here uses exactly the environment a request gives it.
- When to post, what to post, and idempotent posting as a rule of the handlers: F0003 and F0007. The interface only offers the key.
- Wiring that builds the PyGithub `Repository` from the token and picks the concrete adapters: F0002 onward (`factory.entry.wiring`), F0010 for the token.
- The kill-point tests themselves: F0011 (F0008 uses the seam too).

## Decisions taken for the human

Product and design decisions taken while writing the stories, for the human to review in one place. Each names where it was taken.

1. A kill point fires once and is then disarmed; `after` counts the reaches from the arming, not from the start; the reach that fires is counted by `reached`; arming an armed point replaces the earlier arming, and a rejected arming (`after` below 0) leaves an armed point as it was. (S0001, story text)
2. `InjectedKill` is a `BaseException` and not a `FactoryError`, so that no `except Exception` in a handler survives it, as no handler survives a real death. (S0001, story text)
3. The interface sheet gives three modules to later stories that the hosting DTOs already need, and F0001 is built before F0002: S0002 creates the first part of `factory.domain.identifiers` (only `WorkItemId`), `factory.domain.git` (only `CommitId`) and `factory.domain.paths` (only `MAIN_BRANCH` and `LABEL_PREFIX`). S0005 adds `REMOTE`, `RemoteBranch`, `GitIdentity`, `GitOptions` and `GIT_TIME_LIMIT`; S0008 adds `Name`. F0002-S0001 adds the rest of `identifiers` and `paths` and must not create them again. (S0002, story text)
4. A post's key is read only from the last non-blank line of a comment, and a comment counts as the factory's only when it carries the marker (the author is never consulted). A human who quotes a key line neither suppresses a post nor is taken for the factory. `render_post` removes the trailing whitespace of the text before the marker and key lines; `parse_post_key` ignores trailing whitespace and blank lines after the key. (S0002, story text)
5. The PyGithub client gives a merge commit only for a merged pull request, although GitHub reports a test-merge commit for an open one. Only `github.GithubException` and `OSError` (which covers connection errors) become `HostingServiceError`; any other exception passes through as the factory's own bug. `set_labels` reads the pull request's label names to keep those that do not start with `stage:`; this read is internal and never returned, which sits beside R10's "labels are never read back" and is the human's call (the alternative is add and remove calls that need no read). (S0003, story text)
6. The fake hosting service numbers pull requests and comments from 1, uses the url `https://fake.invalid/pull/<n>`, gives its comments the date 2026-10-12 in UTC plus one second per id, posts as the author `factory` and adds human comments as `human` by default. Where GitHub would refuse, the fake does not unless a criterion says so (for example it allows a second open pull request for one branch). (S0014, story text)
7. Every git call ignores the user's and the system's configuration (`GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL` at the null device), has a `time_limit` of 5 minutes by default, and reports the last 30 lines of its output in the error; every failure of `fetch` is a `FetchFailed`. Credentials reach git only through the environment of the factory process and the `environment` of the `GitOptions` given to `GitCli` (for example `GIT_ASKPASS`, or a credential helper setting as `GIT_CONFIG_COUNT` entries), never through global or system configuration and never inside a URL, because git may print a URL and a counted error reports its output tail on the pull request; that is how the factory's own pushes get the token while the agent run does not (WE3.5, R33), and F0010 must not plan a global credential helper. (S0005, story text)
8. `show_file` of a directory is `None`, of an unknown ref a `GitError`; `list_files` of a missing directory is `[]`; `run_process` kills the whole process group at the `time_limit`. (S0005 and S0004, story text)
9. The one `subprocess.Popen` call in `src/factory/adapters/process.py` triggers ruff `S404` and `S603` and bandit `B404` and `B603`. The story carries exactly four suppression markers there (`noqa: S404`, `nosec B404`, `noqa: S603`, `nosec B603`) and a test that allows no others. `CLAUDE.md` already allows exactly these four in that file ("The one exception, decided with the seed"), and `docs/decisions.md` records it, so nothing is asked of the human before S0004 starts. (S0004, story text)
10. The settings of `GitCli` are one frozen model, `GitOptions` (identity, extra environment, kill points, executable, `time_limit`), so that the constructor `GitCli(directory, options)` has two parameters and passes ruff's limit of five without a `noqa` (S0005); the default `GitOptions()` is made inside the constructor (`options` is `None` by default) because ruff's `B008` forbids a call in a default value. The commit identity (`GitIdentity`) defaults to `factory <factory@noreply.invalid>`, v1's compose default, so every `GitCli(directory)` can commit and merge, in every Demo too; the instance's settings `GIT_USER_NAME` and `GIT_USER_EMAIL` (R25) override it through F0010's wiring, and F0010's preflight reports an unset identity (kept thing 18). The identity is set in the environment of every git call, so it is the author and committer of commits and merge commits alike. A push is never forced, and a rejected or unreachable push is a returned value, not an error; `commit` stages everything that is not ignored, untracked files included. (S0005, S0006 and S0012, story text, following the answers for F0001's rounds 1 and 2)
11. `CheckResult.last_line` skips make's own lines (those starting `make:` or `make[`), as v1 does when it writes a check's line into the journal; this refines the interface sheet's "last non-blank line". The output tail is the last 30 lines; a missing target is a failed command, not an error; GNU make exits with 2 whenever a recipe fails, so a recipe's own `exit 3` shows as `exit_status` 2; a `time_limit` of zero or less is a `ValueError`. The make class runs `make --no-print-directory <target>` and removes `MAKELEVEL`, `MAKEFLAGS` and `MFLAGS` from the child's environment, so that a run under `make check` (where the tests run inside make) gives the same output tail as a run on its own. (S0007, story text, following the answer for F0001's round 2)
12. A dead, timed-out or over-budget agent run is a result with an end reason, never an exception; `AgentRuntimeError` is only for a run that cannot be started. (S0008, story text)
13. In the `claude -p` runtime: the flags are those of v1's book, chapter 8 (`--permission-mode auto` and `--permission-prompts none`, both as the book's chapter 8 lists them; the round-1 answer that dropped the second was a mistake of the session, corrected); the resume message reads "Finish now: give your decision (question if the work is not done) and your entry." (v1's `stuck` is gone, `question` replaces it, so a budget stop now reaches the human instead of costing an attempt); the budget case is decided from the reply's `subtype` before the exit status, so a budget stop always reaches the one resume; the resume budget is a quarter of the budget, at least 0.50, rounded half up to cents, and the resume is made once; one `time_limit` counts across both calls; a decision outside `allowed_decisions` makes the end reason `no_result`; `--tools` is always passed (an empty list gives an empty value, which turns the tools off); cost, turns and tokens are taken from the call's JSON in every case except a call ended by the `time_limit`, and a run whose resumed call is ended by the `time_limit` has no cost, turns or tokens at all (R24: nothing partial, nothing estimated); the factory measures the duration itself; a permission denial's detail is the sorted JSON of the tool input; the files under the state directory are removed when the run ends, however it ends. (S0009 and S0010, story text)
14. `changed_paths` is the net difference between the commit and the work tree (a path added and deleted again, or changed and restored, is not listed; a rename is a deletion plus an addition; untracked files count, ignored ones do not); `status` marks any deleted path as deleted, any path that HEAD does not have (untracked or newly staged, also when edited after staging) as added, and everything else as modified. (S0011, story text)
15. `delete_branch` of a branch that does not exist is not an error, and `delete_remote_branch` of a branch already gone from the remote returns `pushed` (as v1: a branch already gone is fine) and removes a stale `origin/<branch>` from the checkout; a merge of diverged branches uses git's default message; a merge that conflicts is aborted before it returns; `reset_to` keeps ignored files (handover section 8); `revert_paths` refuses an absolute path or a `..` segment with `ValueError`. (S0012 and S0013, story text)
16. The skeleton proposed eight stories; the feature has fourteen. S0004 splits the process wrapper from the git wrapper, S0005, S0011, S0012 and S0013 split the git wrapper by what it reads and writes, S0009 and S0010 split the `claude -p` runtime (the call, then the resume and the version), and S0014 splits the fake from the hosting interface, so that every story stays within 26 criteria (S0007 now has exactly 26, S0008 26, S0005 25, S0006 25 and S0013 and the rest fewer; the answer for round 2 allows up to 26). The interface sheet's tags are older than this split; the map from the sheet's stories to this feature's is: the sheet's S0001 is S0001; the sheet's S0002 is S0002 (the interface and its DTOs) and S0014 (the fake); the sheet's S0003 is S0003; the sheet's S0004 is S0004, S0005 and S0011; the sheet's S0005 is S0006, S0012 and S0013; the sheet's S0006 (the make class) is S0007; the sheet's S0007 (the agent-run DTOs and the fake) is S0008; the sheet's S0008 (`claude_runtime`) is S0009 and S0010. This file is authoritative. The test fixtures `remote`, `checkout` (S0005) and `human` (S0006) are built where the first tests need them. (feature, story text)
17. The hook command in the guard settings file is the bare `factory-guard`, found through the `PATH` of the request's environment; the runtime adds no `PATH` to an environment it must not inherit. A request whose environment lacks a `PATH` with `factory-guard` has a guard that cannot start, and Claude Code treats a hook that fails to start as not blocking. The same holds for `HOME`: `claude -p` under the operator's login needs it to find that login, and the runtime adds none. F0005 and F0010 must give the request such a `PATH` and a `HOME`, and F0010's preflight should probe them. (S0009, story text)
18. The `claude -p` flags and the exit status of a budget stop are not checked against the pinned `claude`, because no stand-in can show them. They are a morning observation, tied to F0010's preflight probe (ST5.3), which should run the exact argument list of S0009 once against the pinned `claude`, because a flag it rejects would make every real run end `died` with no text that says why. (S0009 and S0010, story text)
19. Defaults without a source in the handover or run-facts, for the human to confirm: a git `time_limit` of 5 minutes (S0005), a `version()` limit of 30 seconds (S0010), a minimum resume budget of 0.50 (S0010; run-facts gives only "a quarter more"). (S0005, S0010, story text)
20. The factory's interfaces are abstract base classes (`abc.ABC` with `@abstractmethod` operations), and its own implementations inherit them; `typing.Protocol` is kept only for shapes of code the factory does not own. Decided by the human on 2026-10-13, after the feature was accepted with protocols. (S0019, story text)
21. Answers to the open points of the drafts the feature acceptance proposed, decided by the human on 2026-10-13 as the pre-check recommended: an option-like ref, branch, start point or url is refused with `ValueError` before git runs, not passed after `--end-of-options`; every git call runs with `LC_ALL=C` (S0015). A negative `total_cost_usd` counts as a reply that does not parse, like a negative turn or token count, and a budget-stop reply with a negative measure is `died` and not resumed (S0016). An unmerged path stays `"modified"` in `status()`; a kind of its own would be a story of its own (S0017). The documentation repair runs through the pipeline (S0018). (S0015 to S0018, story text)
