# The old hook guard is removed

## Goal

Since F0019 "the write guard by the kernel", every agent run starts through `factory-confine`, which makes the kernel (Landlock) refuse every write outside the run's write paths, tool paths and temporary folder, by any tool and any command. Beside it the older Claude Code hook `factory-guard` still runs: `ClaudeCodeRuntime` writes a guard settings file and a hook settings file for every guarded run and passes `--settings`, so Claude Code starts `factory-guard` before each `Edit` or `Write` and blocks the call on status 2. The hook sees only those two tools, fails open for a payload it cannot read or a call without a file path, and needs its own console script, adapter, entry module, constant, error, preflight check and about forty tests. F0019's decision 16 said the hook goes once a cross-check shows that the two guards agree. The cross-check ran on 2026-10-19 13:44 (`docs/runs/2026-10-12-overnight/night-log.md`): 405 transcripts on `self`; in the 264 runs since the kernel guard went live the hook refused nothing; its only disagreement with the kernel was the temporary folder that F0019-S0011 fixed, besides decision 15's expected one. So this feature removes the hook whole: the runtime stops registering it, then its code, its constant, its preflight check and their tests go, then the documents say that the kernel's guard and the undo after the run are the write guard. The opencode runtime registers no hook today and does not change. What the kernel guard, the undo and the stage still use stays: `GuardSettings` (without the hook's `temporary_directory`), `AgentRunRequest.guard`, `refusal`, `PROTECTED_PATHS` (twelve patterns since F0036), `WritePathService`, `write_targets` and `run_confinement`. It is for the operator, who has one guard to know and one fewer command to install, and for the human, who keeps less code. Done when every story below is merged and `make check` is green.

## Scope

- `src/factory/adapters/claude_runtime.py`: no hook settings, no guard settings file, no `--settings` (S0001).
- The rule R14 of the seven shipped agents under `claude/agents/` loses its hook clause (S0001).
- `src/factory/adapters/claude_guard.py` and `src/factory/entry/guard.py` are deleted; `GUARD_COMMAND` (`factory.domain.agent_runs`), `GuardSettingsInvalid` (`factory.domain.errors`), `GuardSettings.temporary_directory`, the wiring's re-exports `judge` and `read_guard_settings`, and the preflight's search for `factory-guard` in the item `agent-environment` go (S0002).
- The tests of the hook and of its wiring: deleted or changed under decisions 9 and 10 (S0001, S0002).
- `tests/entry/test_watch.py`: the follow-mode search reads only the Python sources, under decision 14 (S0004, proposed by the acceptance).
- `README.md`, `docs/operator-guide.md`, `docs/project-guide/` and `docs/decisions.md` (S0003).
- The human's changes: the console script and the mutmut deselect in `pyproject.toml`, the R12 bullet in `CLAUDE.md`, and the operator's check after the merge.

## Out of scope

- The kernel's guard: `factory-confine`, `factory.adapters.landlock`, `factory.domain.confinement`, `run_confinement`, the preflight item `confinement`, `tool_paths`. Unchanged.
- The undo (`UndoService`), `refusal`, `is_writable`, `matches_any`, `PROTECTED_PATHS` and `WritePathService`: the undo still judges every changed path through `refusal` after every run. Unchanged.
- `AgentRunRequest.guard` and the name `GuardSettings`: the kernel's rules and the undo are built from them (decision 4).
- The opencode runtime: it registers no hook and passes no `--settings` today.
- The Claude Code `permission_denials` reading (`_PATH_KEYS`, `denied_path`) and the switch `PYTHONDONTWRITEBYTECODE`: they serve the runs, not the hook (S0001 rewords one comment only).
- `claude/settings.json` (the shipped permissions): it holds no hook; it reaches the agent through its home, not through `--settings`.
- `image/`, `template/` and `demo/`: none of them names the hook (searched on 2026-10-20; the `detect-secrets-hook` of the Makefiles is another tool). The image installs the console scripts from `pyproject.toml`, so the human's change 1 is what takes `factory-guard` out of it.
- The entries of `docs/decisions.md` written before this feature: they stay as history; S0003 adds one line to each that the removal supersedes.
- Every paid call: no story and no smoke test makes one.

## Decisions taken for the human

1. **The documents change in one closing story, S0003** (open; A recommended). A: S0001 and S0002 have the docs criterion `none` and S0003 rewrites every passage once the hook is gone whole; for the two merges in between the documents still describe a hook that S0001 stopped registering and S0002 deleted. 2. **The preflight item `agent-environment` checks the agent run's `HOME` only** (open; A recommended). A: `agent_environment_item(environment, is_directory)`; the search for `factory-guard` and the fault `the agent run has no PATH` leave it, because the item `confinement`, which runs right after it, already reports `the agent run has no PATH` and searches the `PATH` for `factory-confine`. B: the item keeps the `no PATH` fault, so a missing `PATH` is reported twice. C: the item goes and the `HOME` check moves into `confinement`; that renames what the operator sees for a fault of the login's home. (S0002)
3. **`GuardSettings.temporary_directory` goes** (open; A recommended). Only the hook read it (F0019-S0011); the kernel's rules carry their own temporary folder (`Confinement.temporary_directory`) and the instance its own (`InstanceSettings.temporary_directory`). A: the field goes, so a settings value cannot name a folder nothing reads. B: it stays unused. (S0002)
4. **`GuardSettings` and `AgentRunRequest.guard` keep their names.** They now describe what the kernel's rules and the undo are built from; a rename touches about twenty modules and their tests for no change in behaviour. (S0002)
5. **The hook's fail-open rule goes with it, and nothing replaces it.** The hook allowed a tool call whose payload it could not read or that named no file path (v1's rule); the kernel judges every write by its real path, with no exception, and the undo judges every changed path after the run. (S0002)
6. **A protected path inside an allowed folder is reverted after the run, not refused during it** (open; A recommended). F0019's decision 15 and F0036's decision 2: the kernel cannot exclude a protected path (`docs/x/feature.md`, `src/.claude/...`) inside a folder a write path opens. Until now the hook refused such an `Edit` or `Write` in a Claude Code run, and the undo reverted it in every run, opencode's included. A: from S0001 on a Claude Code run is treated as an opencode run is today: the write lands and the undo reverts it after the run; the agent learns it only from the undo record. The cross-check found no such attempt. B: keep a reduced hook for the protected paths only; that keeps the code, the console script and the preflight check this feature removes. (S0001)
