# F0050 eval: time and token savings

## F0050-S0001 (the base image holds only the instance's runtime), 2026-11-04 UTC

The work item was still in `in-progress/` when it was read, at the end of its second smoke test (`approval`). Its transcripts are 20 sessions: the 19 runs in `.costs.jsonl` and one crashed documenter run that has no cost record (see finding 7).

### 1. Totals

- Runs: 19 (intake 2, tester 3, coder 7, reviewer 3, documenter 2, smoke-tester 2). Turns: 159.
- Tokens: input 266, output 114,332, cache read 4,698,798, cache creation 631,115.
- Cost: $7.72 (tester $2.40, coder $2.50, reviewer $1.80, smoke-tester $0.50, documenter $0.40, intake $0.20). The first tester run alone cost $1.95 (25 percent of the story) and the first coder run $1.13.
- Time: runs 1,746 s of wall time, 1,256 s of model time; the story clock ran 08:44:36 to 09:40:20, about 3,344 s. So 38 percent of the story's time was the model, 15 percent was run time outside the model (almost all of it `make check`), and 47 percent was gaps between runs (three human answers, the factory's own checks, one crash retry).
- Fitted prices from the 19 records: about $17.8 per million output tokens, $7.4 per million cache-creation tokens, $0.44 per million cache-read tokens. I use these for the estimates below.
- Output tokens are about 47 percent hidden thinking (about 54,000 of the 114,000: tester run `d34ce2cc` 27,000 of 43,800; coder run `85f84eef` 16,000 of 21,000; reviewer run `1edb1336` 8,300 of 10,400).
- Comparison with F0049 stories of similar size: F0049-S0003 (a changed stage file is rebuilt) had 16 runs, $5.86, 162 turns; F0049-S0001 (the factory's own tools live apart) had 22 runs, $6.60; F0049-S0002 (a project's stage file builds its image) had 21 runs, $15.10 and one human answer. So this story sits in the middle; it is not a runaway, but about $3 of it was avoidable rework.

### 2. Findings, ordered by estimated saving

**1. The story's own smoke test was wrong, and the mistake was found only after review and docs had run once.** Evidence: the `## Smoke test` expected `grep -cE '^ARG AGENT_RUNTIME$' vm/Dockerfile` to print `1`; the criteria (a check per stage, "no default") need one `ARG` per stage. The smoke-tester run `025dbcf1` found it at 09:28; the coder run `45d4068b` stopped with a question, the human chose option B, and then coder `6b556d4d`, reviewer `22ab12e6`, documenter `9626916d` (plus the crashed one) and smoke-tester `8482a79d` ran again. That chain cost $1.58 ($0.44 + $0.25 + $0.44 + $0.11 + $0.22 + $0.12 uncounted) and about 10 minutes of story clock including the human wait. Saving: about $1.5 and 8 to 10 minutes per story that has such a mismatch. Proposed change: a rule in `claude/agents/coder.md`: "Before you end with `review`, run the commands of the work item's `## Smoke test` once, in the same command as your last `make check`; if one does not meet its `Expect:`, that is a question now, not after review." The smoke test stays independent (the smoke-tester still runs it); this only moves the discovery forward by four stages. The cost of the rule is about 10 s per story. Risk: the coder may bend the code to a wrong `Expect:`; the rule says to ask, not to bend.

**2. The tester is told to skip the type check, so untypable test code reached the coder and cost a human answer and three relay runs.** Evidence: `claude/agents/tester.md` step 3 says "Skip the type check in this stage". The tester run `d34ce2cc` ran `make lint` and narrow pytest only; the coder run `85f84eef` ran `make check` and found `tests/test_stage_image.py:663: error: Cannot infer type of lambda`. It could not edit tests, so it asked (journal entry 10). The human answered (entry 11) and three runs followed only to move that text: coder `b250f19d` ($0.11), tester `b58bd32f` ($0.18), coder `b78e1e41` ($0.16, 111 s of which 94 s was `make check`). That is $0.45, about 150 s of run time and 3.5 minutes of story clock, plus a human interruption. This story added no new module, so `make types` could have run clean. Saving: about $0.45 and one human question when it happens. Proposed change: in `tester.md` step 3, replace the skip with "Run `make types`. Accept only errors that say a module or name under test does not exist; any other error in your test files (an untypable lambda, a missing annotation) you fix yourself."

**3. Relay runs: the coder is woken only to pass a test change to the tester and then to confirm it.** Evidence: two chains, each coder, tester, coder: `b250f19d`/`b58bd32f`/`b78e1e41` (lambdas) and `fb344571` ($0.24, 5 turns), `0713aaeb` ($0.22), `486d7252` ($0.19, 115 s of which 96 s was `make check`) for reviewer finding 1 (move the duplicated helper to `tests/dockerfile_support.py`). The coder's entries say "No code changed this round" (entries 17 and 25). The four coder relay runs cost $0.70 and 259 s of run time, and the factory runs `make check` again after each (gaps of about 115 s at 09:16, 09:23 and 09:34). Saving: about $0.70 and 5 to 8 minutes per story with a reviewer finding in test code. Proposed change, two options for the human: (a) a pipeline setting that lets the tester hand a leave-based test change (`Mode: a test change the human approved`, or the standing leave in CLAUDE.md) straight to the stage it came from (`next: [doing, review]` for `tests`, with the check `check`); or (b) a rule in `reviewer.md` that a finding about a test file under a standing leave goes to the tester directly (the reviewer's `next` lists `tests`). Option (a) is smaller.

**4. The coder runs `make check` itself in rounds where it changed nothing, and the factory runs it again right after.** Evidence: non-model time in coder runs `85f84eef` 104 s, `b78e1e41` 94 s, `486d7252` 96 s, `6b556d4d` 98 s (duration minus model seconds), 392 s in all, and `coder.md` step 6 says "The factory runs `make check` after you". The rounds with no code change (`b78e1e41`, `486d7252`) ran the check once in the run and once in the factory's gap of 114 to 118 s. Saving: about 190 s per story with such rounds. Proposed change: in `coder.md` R11, add the exception the documenter already has (`documenter.md` line 77): "When you changed no file this round, end without running `make check`; the factory runs it right after and that run decides."

**5. The whole work item is dumped into the context several times per run, and a dump above about 30 KB is saved to a file and then read again.** Evidence: the characters of tool results that came from the work item (`cat`, or a `Read` of a saved result) were 571,000 over the 20 sessions (about 145,000 tokens), with 12 runs over 30,000 each: coder `85f84eef` 58.7 KB, documenter `c14f4261` 47.9 KB, coder `45d4068b` 48.1 KB, coder `6b556d4d` 51.2 KB, reviewer `22ab12e6` 53.2 KB, documenter `9626916d` 42.6 KB. In coder `486d7252` the journal went through three times in one run: a `cat` (34.9 KB, saved to a file), an `awk` variant (32 KB, saved), then a `Read` of the saved file (33.6 KB). Quote: `Output too large (34.9KB). Full output saved to ...`. The work item grew from 4.9 KB to 60 KB because the reviewer's "what I checked and found sound" and the smoke-tester's pasted outputs go into the journal. Saving: if each run read the front matter, `## Description` to `## Smoke test`, and the last four journal entries (about 10 KB), the reads would shrink by about 370,000 characters, or 90,000 tokens, which is about $0.8 per story at the fitted prices (one creation plus about six cache reads each), and fewer turns spent re-reading. Proposed change: a rule in the shared part of the agent files (R5 area): "Never `cat` the whole work item. Read it with one `awk` from `## Description` to the end of `## Smoke test`, then only the last four journal entries; the prompt gives the entry count." A stronger change: the factory writes that slice into the prompt. Also cap the reviewer's "found sound" list (for example five lines), because every later run reads it.

**6. Later review rounds re-read the whole diff, not the change since the last review.** Evidence: reviewer `1edb1336` (round 1) read 66.7 KB of diffs in 8 turns; round 2 `e8718e1d` read 37.8 KB (the 24.9 KB test diff again) in 12 turns; round 3 `22ab12e6` read 24.8 KB, although its own entry says the only change since round 1 was two lines of the Dockerfile. Saving: about $0.25 and 30 to 40 s per story with more than one review round. Proposed change: in `reviewer.md`: "On a later round, read `git diff <commit of the last review>..HEAD` first; read the full diff only if that delta touches a file the earlier findings name." The factory would put the last reviewed commit in the prompt.

**7. A crashed documenter run is missing from `.costs.jsonl`.** Evidence: journal entry 40 "crash 1: the run of stage docs ended without a result"; transcript `f7dd4ad2` (09:36:19 to 09:36:34, 15 s) has no cost record, and its last budget attachment shows `$0.1234195/$1.5` used. So the story's real cost is about $7.84, not $7.72, and the gap between the crash and the retry was 93 s. The cause is not visible (the transcript ends after a tool call with no result). Saving: none in tokens; it is a measuring gap. Proposed change: write a cost record for a crashed run too (status `crashed`), from the last budget attachment; this fits F0050-S0002 (the cost records show the machine) or F0050-S0006 (the cost record sums up the run's tool calls).

**8. The first tester run is the most expensive single run: 24 turns, 488 s, $1.95, 27,000 tokens of thinking.** Evidence: run `d34ce2cc` wrote about 37,600 characters of tool input (a test file that grew to about 1,060 lines, mostly one parametrized refusal row per clause) and began with whole-file reads: one command `cat tests/test_stage_image.py; cat vm/Dockerfile; grep ...` returned 29.7 KB, the next `cat tests/dockerfile_support.py` 10 KB. It also edited `vm/Dockerfile` and `vm/job-start.sh` by hand to see rows fail, then restored them with `git show HEAD:...`. Saving: unclear; the ten criteria and the rows they name explain most of the size. I propose no rule; the lever is in the story (criteria that name each refused row make a big test file). To be compared with other tester runs before concluding.

### 3. Carried over

This is the first report, so there is nothing earlier to confirm or refute. Findings 2, 3, 4 and 5 are the ones most likely to recur in any story with a reviewer finding or a human question in test code; check them first in the next report.


## F0050-S0002 (the cost records show the machine), 2026-11-04 UTC

The work item was merged and had moved to `done/` when it was read. Its transcripts are 23 sessions in `session-logs/vm-f0050/F0050-S0002/-work-checkout/`: the 21 runs in `.costs.jsonl` and two crashed tester runs that have no cost record (finding 8). The copy also holds the transcripts of F0050-S0001 (the base image holds only the instance's runtime), which I did not use.

### 1. Totals

- Runs: 21 (intake 2, tester 6, coder 8, reviewer 3, documenter 1, smoke-tester 1). Turns: 287.
- Tokens: input 514, output 153,065, cache read 11,692,725, cache creation 865,446.
- Cost: $11.83 (coder $4.57, tester $3.57, reviewer $2.92, documenter $0.32, smoke-tester $0.27, intake $0.18). The two crashed tester runs add about $0.86 that is not in the file (finding 8), so the real cost is about $12.69. The most expensive single runs: the first coder run `87b4e6dc` $2.44, the last tester run `90750c0b` $1.15, the first reviewer run `eb5e77c5` $1.11.
- Time: the story clock ran 10:12:34 to 12:22:43, 7,809 s. Human waits (six answers) were 3,207 s, 41 percent. The runs took 3,143 s, 40 percent, of which the model was 1,786 s (23 percent of the story clock); 1,357 s was run time outside the model, 95 percent of it in coder runs. The remaining 1,459 s (19 percent) are the gaps between runs, the crash handling around 10:39 to 10:45, and the wait from the smoke test to the merge. The factory's own check after a coder run was short this time: 6 to 10 s between the end of every run and the next start, because it reuses a pass of the same tree (entry 52 says "not run again: passed on tree"). In F0050-S0001 the same gap was 114 to 118 s.
- Comparison: F0049-S0002 (a project's stage file builds its image) had 21 runs, $15.10 and one human answer. This story has the same number of runs, is $3.27 cheaper, and had six human answers. F0050-S0001 had 19 runs and $7.72. The cost went to the tester (30 percent, with the crashes) and to rework rounds, not to the coder's first build.

### 2. Findings, ordered by estimated saving

**1. The reviewer found the missing tests, not the tester, and each such finding cost a round.** Evidence: the findings of round 0 (`eb5e77c5`, entry 31) included test gaps: no test took a record through `CostRecorder.begin` and then `complete`; `PodmanImages.size_bytes` and `store_path` had no test; criterion 11's rows were missing. The reviewer of round 1 (`9565f6c5`, entry 42) found two more: "With `machine=None` every test passes too" (the wiring in `build_boundaries`), and the start-side log line through `run_instance`. The code was right each time; only tests were added. The chain after the second review alone was coder `42de879d` ($0.24), tester `52dd5680` ($0.40), coder `03e8169f` ($0.14, of which 96 s was `make check`) and reviewer `6d030fc6` ($0.72): $1.50 and about 5 minutes. Saving: about $1.5 per story with such a finding, up to $2.5 if the first chain is also avoided. Proposed change: in `claude/agents/tester.md`, add "For every new object the Interface says the factory wires (a field of `Boundaries`, a call in `run_instance`), and for every new method of a real adapter that calls a program, write one test that fails when the wiring or the call is removed or replaced by `None`; the fakes alone do not show that." The cost is a few more rows in the first tester run.

**2. The story did not name its seams, so the tester asked twice and each answer cost a human wait.** Evidence: entry 8 (`1a7a8f1e`, 67 s) asked for the names of the modules and functions, and entry 9 answered after 649 s. After two crashes the tester run `965b23d0` ($0.60, 131 s) asked again (entry 17), because criteria 2, 3, 7 and 9 reach the record only through seams that entry 9 had not named (`MachineTotals`, `MachineReadings`, `Boundaries.machine`); entry 18 answered after 495 s. The third run `90750c0b` ($1.15) wrote everything. Quote: "nothing named yet reaches it". `claude/agents/tester.md` and `factory/story-form.md` say nothing about seams. Saving: $0.60 and 1,144 s (19 minutes) of human wait per story whose Interface lacks names. Proposed changes: (a) in `tester.md`: "When a criterion cannot be tested without choosing a name, collect every such name for all criteria and ask once, in one question; do not stop after the first criteria that you can write." (b) in `factory/story-form.md` and `intake.md`: "The Interface names every module, function, class and signature that a test must call; intake asks for what is missing." Intake already found six other gaps in this story for $0.12, so (b) fits its job.

**3. The whole work item is dumped three times at the start of every run, and the biggest dumps are read again from a saved file.** Evidence (confirms S0001's finding 5): the work item grew to 89,797 bytes (Description to Smoke test 8.6 KB, nearly all the rest journal). Tool results that came from the work item were 361 KB in the 23 sessions, and the reads of saved result files were another 549 KB (most of them the journal and the review diffs). A coder run starts with `cat <work item>`, then `awk` over the same file, then a `Read` of the saved copy: `77427182` read 59,998 bytes that way, `6ff2ad67` 42,674, `e4f619d0` 39,069, `e1c60f80` 31,077. Quote: "Output too large (...). Full output saved to ...". The five tester starts read 13.6, 18.6, 19.0, 20.3 and 27.6 KB. Entries 22, 31 and 37 are 6.6, 5.7 and 3.1 KB, and repeat what earlier entries said ("Built across the doing runs"). Saving: about $1.0 per story (about 90,000 tokens at one creation and about six cache reads each) and two to three turns per run. Proposed change as in S0001: the factory writes the slice into the prompt (Description to Smoke test, then the last four journal entries), and the shared rules say the journal before the last four entries is history and is not read. A rule that a coder or reviewer entry lists its files once, in the first entry only, would also shrink every later run.

**4. Relay runs: the coder is woken only to hand a test change on, and then again to confirm it.** Evidence (confirms S0001's finding 3): `2846c67e` ($0.19, 34 s, entry 25: "I changed no code"), `42de879d` ($0.24, entry 44) and `03e8169f` ($0.14, entry 48, 96 s of it `make check`) did nothing but pass a message. Together with `9c6ab98d` and `b7d53bb9` (finding 5) that is five coder runs without a code change, $1.10. Saving: $0.57 and about 3 minutes for the three pure relays. Proposed change as in S0001: let the tester hand a test change that a leave allows or a reviewer finding names straight on to `review` (`tests: next: [doing, review]`), with `make check` as the check on that path. This time the leaves were exact (entry 23), so the tester could not have gone wrong.

**5. The coder is told to edit the criteria, but the pipeline does not let it; the edit was dropped and the human was asked.** Evidence: `claude/agents/coder.md` R5 says a criterion the answer adds is written by the role, and entry 33 says the coder rewrote criterion 13. The factory dropped the edit, because the coder's `write_paths` in `factory/pipeline.yml` do not hold `{work_item}`, so the reviewer's finding 6 (entry 31) stayed open. Coder `9c6ab98d` ($0.28, 96 s `make check`) asked (entry 37), the human answered after 360 s with a leave for the reviewer (entry 38), coder `b7d53bb9` ($0.25, 96 s `make check` on a tree nobody had changed since the check 96 s before) ended, and the reviewer made the edit. Saving: $0.53, about 190 s of run time and 6 minutes of human wait. Proposed change: in `coder.md` R5, replace the sentence with "You never edit the work item. If the journal asks for text in a criterion (for the documenter, for example), write it in your entry under 'For the reviewer'; the reviewer adds it to the criterion." Giving the coder the work item as a write path is the other option; I do not recommend it.

**6. The first coder run waited 706 s for full test suites it did not need to repeat.** Evidence: `87b4e6dc` had 427 s of model time and 1,133 s of wall time. Its long commands: `make test` 85 s (11:22), `make test` again 86 s with a different grep (11:24), `make test` a third time 87 s (11:27), a narrow `pytest` over `tests/adapters`, `tests/domain` and more that took 335 s (11:29; I cannot see why, since the full suite takes about 86 s), and the final `make check` 91 s (11:35). The first run already showed the failing tests; the reruns only changed the grep. Saving: about 170 s (the two reruns) per story with a long first coder run, up to 400 s if the 335 s command was avoidable. Proposed change in `coder.md` near R11: "Run `make test` once to learn which tests fail and write its output to a file to search; then run only the failing tests until they pass, and `make check` once at the end." Also, when the tree is the one you checked in an earlier run and nothing changed, do not check again (the 96 s of `b7d53bb9`).

**7. The reviewer reads the whole diff again in every round.** Evidence (confirms S0001's finding 6): round 2 `aae08744` read the 63,276 bytes of work item and then the same 39,217 bytes of source diff that round 1 `1c0c0cec` had read (same size), although its own entry says only two test files changed since the last review and nothing under `src/`. Tool results per review run: 133 KB (`487a878c`), 169 KB (`1c0c0cec`), 133 KB (`aae08744`). Saving: about $0.25 and 30 s for the round 2 review. Proposed change as in S0001: the prompt gives the commit of the last review, and `reviewer.md` says to read `git diff <that commit>..HEAD` first.

**8. Two paid tester runs have no cost record, and their work was lost to a refused push.** Evidence (confirms S0001's finding 7): transcripts `da81cf62` (10:36:57 to 10:39:05) and `3ce35549` (10:40:05 to 10:41:54) both end with the full structured output, and their last budget lines read $0.4396 and $0.4173 spent. The journal (entries 11, 13) says "ended without a result" and "work is discarded"; the human's guess in entry 15 is a refused push in GitHub's incident (see `planning/outage-2026-11-04.md`). I found no key or token in these transcripts. Entry 55 says 21 runs and $11.83, so about $0.86 and 237 s of run time are missing from the bill. The tester then did the same work a third time (`965b23d0`, `90750c0b`). Saving: none by an agent rule; this is a measuring gap and a factory fault. Proposed changes: write a cost record with status `crashed` from the last budget line (F0050-S0006, the cost record sums up the run's tool calls, is the place), and let the factory retry the push a few times with a pause before it calls a run crashed, so that a finished run is not thrown away for a short outage.

### 3. Carried over

From the S0001 section: finding 3 (relay runs) is confirmed and sharper, see finding 4 here. Finding 5 (the work item dumped) is confirmed with the saved-file rereads measured, finding 3 here. Finding 6 (the whole diff again) is confirmed, finding 7 here. Finding 7 (crashed runs without a record) is confirmed with two more runs, finding 8 here. Finding 4 (the coder's `make check` in a no-change round) is partly refuted: the factory's own check after a coder run took 6 to 10 s, not 115 s, so only the coder's own duplicate remains (`b7d53bb9`, 96 s).
