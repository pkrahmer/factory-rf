name: stage-doing
description: Stage instructions for `doing`. Preloaded into the coder agent; not invoked directly.
---

1. Read the ticket and the files its last log entries name (the tester's test files; on a rework round, the findings), in one command where you can. `CLAUDE.md` is already in your context. Read the project's documentation where `CLAUDE.md` points you to it (an architecture change, a decision to respect or cite), not as a tour before you start. Do not read the Makefile, `pyproject.toml` or tool configuration; `make check` enforces what they say. Nothing else: not other tickets, not `FEATURE.md`, not `factory/`, not `.claude/`. If the task's round is greater than 0, address exactly the findings in the latest entries, nothing more.
2. Implement as the role skill describes until `make check` is green. A test that cannot pass against the ticket (contradicts the interface, is non-deterministic) is a question (R8, R9): describe the test and the options and end with `question`. When you arrive with the human's answer in the log and it calls for a test change, do not touch the test: end with `tests` and an entry naming the test and the change in one sentence. The tester makes the change and sends the ticket back.
3. Commit as you go with messages `ticket <id>: feat(<layer>): <what>`. One commit per coherent change is fine.
4. Refactor, once. With `make check` green, read your own diff (`git diff main...HEAD -- . ':!factory' ':!tests'`) the way a reviewer would: rename what is unclear, simplify what is convoluted, remove duplication and dead code. Add nothing. Behaviour stays the same, tests stay untouched, `make check` is green again afterwards. Commit separately as `ticket <id>: refactor(<layer>): <what>` so the reviewer sees feature and clean-up apart. Chain each final `make check` with its commit in one command (`make check && git add -A && git commit -m …`), so checking and committing cost one turn. If nothing needs changing, say so in your entry. A restructuring beyond this ticket is a new ticket, not a refactor (R13).
5. Rewrite `## Assignment` only if a log entry changed the meaning of the task; then update its "as of" heading.
6. End with `review` and an entry: what you built (paths), the main design decision and the alternative you rejected, anything you noticed but did not touch. The factory runs `make check` after you; red holds the ticket here.
