# Audit of F0007 (the human on the pull request), round 1

## Summary

- 7 blockers, 15 should-fixes, 15 notes. The form holds: every story has the five sections of `factory/TICKET.md`, criteria numbered 1 to n (10 to 22, at most 26), the closing pair (`make check stays green.`, then `docs:`), an `Expect:` after every fence, no heading inside a fence, no clock time and no front matter. No new dependency, and every write is in `src/*`, `tests/*` or the documenter's files.
- Blocker 1: no handler inherits F0006's `Handler`, which is an abstract base class. `CLAUDE.md` requires the inheritance, and `dict[EventKind, Handler]` does not type-check without it.
- Blocker 2 (Q20): S0010 builds `human_handlers` in `factory.application` and leaves the wiring to F0006. It should register the handlers in `factory.entry.wiring.build_handlers` and shrink `NOT_YET_HANDLED`. F0006-S0007's c4 and c5 tests break when it does.
- Blocker 3: `AskHandler` has no rule for `blocked == "attempts_cap"`, so the retry after a failed or killed post (S0002 c12 to c14) is unspecified.
- Blocker 4: `RejectHandler` reads the branch's head commit. F0006's move rule reads the newest commit beyond `origin/main` that touched the work item. A later commit on another path leaves the illegal change in place, and the handler raises on every tick.
- Blocker 5: S0007's second Demo has a real line break inside a Python string, so it fails with a `SyntaxError`.
- Blocker 6: S0001's `CopyResult.commit: CommitId` and its models have no closed-model or type-limit criteria (the intake refusal of F0005).
- Blocker 7: a comment written while the stages work answers the next question before it is posted. F0006 raises `comment` ahead of `ask`, so the question never reaches the human (kept thing 10).
- Questionnaire 1: only Q20 changes F0007. Q3, Q15 and decision 008 need no edit here; Q6, Q7, Q8, Q12 (b) and Q28 confirm the drafts.
