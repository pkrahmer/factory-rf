# Audit of F0003, round 1: stops and the pipeline definition

## Summary

- 3 blockers, 14 should-fixes, 15 notes, over FEATURE.md and the five drafts.
- Blockers: S0001 still builds the stop reason `v1_work_item_found`, which Q15 and decision 008 drop. S0003 writes a second translator for validation faults, with other spellings than the one F0002 built (`factory.adapters.validation_faults`: `missing key: <path>` and so on, documented in the project guide). S0004 reads agent front matter "with python-frontmatter" and names no ruamel.yaml handler. python-frontmatter's default handler is PyYAML, which breaks R13 as kept literally. F0002's `RuamelYamlHandler` exists for this.
- Main should-fixes: no implementation is written as inheriting its abstract base class. Some limits are tested on one side only (`PositiveInt`, `AwareDatetime`, the Literals, unknown keys). The required fields that S0003 and S0004 add to `Boundaries` break earlier tests. S0003 c9 and c13 accept cases that S0005's rules then refuse, so S0005 would have to change S0003's tests. An unreadable `health.json` is not covered. Cross-check 11 (a draft pull request for a branch the remote does not have) is still open. Several interface rules in S0001, S0004 and S0005 have no criterion. Nobody owns raising the loader's stop, between S0004 and F0006-S0004/S0006. A semgrep trap (`yaml.load`) is not warned of.
- Order, write paths, dependencies, form (sections, closing criteria, `Expect:` lines, no headings in fences, no clock times) and the Demos all hold: each `Expect:` was traced against the built code and the stories' rules. No story exceeds 26 criteria.
- Questionnaire 1 touches F0003 at Q15/008 (S0001), Q3 (S0001), the abstract base class decision (S0001, S0003, S0004) and Q20 (wording only). Q17, Q22 and Q23 do not touch F0003. Six places need the built spelling of F0001 and F0002; the exact edits are below.
