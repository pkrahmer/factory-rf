# Audit of F0004 (claim and write paths), round 1

## Summary

- 3 blockers, 14 should-fixes, 9 notes. Size, numbering, closing criteria, `Expect:` lines and write paths pass. No draft needs a new dependency or writes outside `src/*` and `tests/*`.
- Blocker 1: the demos of S0001, S0003 and S0005 import `factory.adapters.run_record_file` and pass `run_record=` to `Boundaries`. Q3 dropped the run record, so all three demos fail on the import.
- Blocker 2: S0004's `main(argv, *, stdin, stderr)` has required arguments, and its `run()` entry point does not match `pyproject.toml`. `pyproject.toml` already registers `factory-guard = "factory.entry.guard:main"`, and every entry function is `main() -> int`. As drafted, the hook would crash with a `TypeError`. Claude Code treats a crashed hook as non-blocking, so the guard would silently fail open.
- Blocker 3: S0005 finds the other work items in progress with F0002's built `folder_of`. That function returns `None` for a `.costs.jsonl` sidecar. So the promised undo of the cost-record file "whatever the write paths say" cannot happen, and criterion 7 passes only because its write path `*.md` excludes the sidecar.
- Main should-fixes:
  - S0002 c10 builds a definition that F0003-S0007 refuses (`lease_duration` 5 is less than the default `time_limit` of 40).
  - S0002's name search would fail on F0006-S0002's parameter `claim_status`.
  - S0001 contradicts Q2 A (the opening commit is the first stage's claim) and has no criterion for a branch that is not yet on the remote.
  - S0003 bypasses `PipelineLoader` and re-spells the constants of F0002 and F0003.
  - S0004 cites F0001-S0008 for the runtime, but that is F0001-S0009 and already built.
  - Several S0005 test setups are ambiguous.
