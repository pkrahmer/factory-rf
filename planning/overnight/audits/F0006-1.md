# Audit of F0006 (reading the remote), round 1

## Summary

- 7 blockers, 18 should-fixes, 10 notes. The form holds: every story has the five sections of `factory/TICKET.md` and its criteria are numbered (21 to 24 each, at most 26). The closing pair is in place, every fence is followed by `Expect:`, no heading sits inside a fence, and there are no clock times or front matter. No story needs a new dependency or writes outside `src/*`, `tests/*` and the documenter's files.
- Blocker 1 (Q20, cross-check 1 blocker 1): no story builds `build_dispatcher` or the `run` handler around `StageRunner`, or supplies the agent run's environment that F0005 decision 23 expects from F0006. FEATURE even hands the work back to F0005, and F0005 hands it to F0006. The tick also takes a ready-made `Dispatcher`, but the handlers need the definition the tick loads.
- Blocker 2 (Q15, decision 008): S0001, S0002, S0004, S0005 and FEATURE still build the v1 recognition, its event and its stop. The built `RepositoryStopReason` has no `v1_work_item_found`, so S0004 c13 cannot pass.
- Blocker 3 (Q3): the S0003 and S0004 Demos import `factory.adapters.run_record_file` and pass `run_record=` to `Boundaries`. Neither exists, so both fail. S0004 c15 and c16 and S0006's `running_since` still read the run record.
- Blocker 4: S0004 raises and clears `pipeline_definition_invalid` itself, against F0003's built rule that only the loader does so. Every refusal would write a second stop line.
- Blocker 5: S0004's Demo expects three lines. `TimestampedFactoryLog` writes the stop's stamped lines to standard output first, and the git error spans several lines.
- Blocker 6: S0006's `main` needs keyword arguments, but the existing console script calls `main()`. Run for real, `factory-watch --follow` dies with `TypeError`, not with argparse's unknown option (SI3.1; cross-check 1 finding 8).
- Blocker 7: no story has the type-limit and closed-model criteria that intake refused five times in F0005.
