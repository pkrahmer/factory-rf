# Audit of F0001-boundaries, round 1

## Summary

- 1 blocker, 13 should-fixes, 20 notes, over FEATURE.md and the eleven stories S0001 to S0011.
- Blocker: S0006's first Demo expects `lint failed 3`. GNU make exits 2 whenever a recipe fails, so the correct code prints `lint failed 2` and the smoke test can never pass.
- Criteria that the correct code cannot meet: S0011 criterion 17 (the `HostingService` protocol also defines `post_comment`) and S0008 criterion 5 (a Python stand-in started with an empty environment adds `LC_CTYPE` itself, by PEP 538). S0008 criterion 18 contradicts itself.
- Real-runtime risks that the stand-in tests cannot catch: S0008's flag `--permission-prompts none` is in neither the handover nor run-facts. Its precedence of exit status over `error_max_budget_usd` is unchecked, so the budget resume may never run against the real `claude`.
- Design points for the human: the hard-coded commit identity (kept 18's preflight "identity set", R25) and the ignored global git configuration (how git gets its token for WE3.5).
- Size: S0004 and S0008 each carry 25 criteria with many mechanisms, which is tight for the tester's $2, the coder's $4 and a 60-minute lease.
- Form is clean: sections, numbering, the two closing criteria, `Expect:` after every Demo block, no heading lines inside fences, no front matter and no clock times. No story needs a story with a higher id, and none needs a new dependency or a write outside the write paths.

## Findings

| # | Story and section or criterion | Finding | Severity | What would fix it |
|---|---|---|---|---|
| 1 | S0006, Demo, first block | The Makefile's `lint` recipe runs `exit 3`. GNU make reports `Error 3` but exits with status 2 whenever a recipe fails, so `MakeProjectCommands` returns `exit_status == 2` and prints `lint failed 2 'lint: red'`. The `Expect:` line asks for `lint failed 3 'lint: red'`, which no correct implementation can produce. The smoke test sends the story back to `doing`, and the coder cannot fix it. The story's own rule already knows that make exits 2 for a missing target. | blocker | Change the expectation to `lint failed 2 'lint: red'`, and say in it that make, not the recipe, sets the exit status. |
| 2 | S0011, criterion 17 | "Exactly `FakeHostingService` and `PyGithubHostingService` define a method named `post_comment`" among the classes of `src/factory`. But the `HostingService` protocol of S0002 (`factory.application.hosting`) is a class in `src/factory` that defines `post_comment`. A test written to the letter fails on correct code, and the coder cannot change the test. | should fix | Write "among the classes of `src/factory` other than the `HostingService` protocol", or "among the concrete (non-`Protocol`) classes". |
| 3 | S0008, criterion 5 | The stand-in is a Python script. With an empty `request.environment` there is no locale variable, so CPython's locale coercion (PEP 538) sets `LC_CTYPE=C.UTF-8` in the stand-in's own `os.environ`. A test that compares the recorded environment for equality with `request.environment` plus the three switches then fails on correct code. | should fix | Have the test's request environment carry `LC_ALL=C.UTF-8` (no coercion then), or state the criterion as: every given variable and the three switches are present with their values, a test-process variable is absent, and no other variable is present except `LC_CTYPE`. |
| 4 | S0008, criterion 18 | "Without kill points, and with the point unarmed, `run` returns normally and `reached(AGENT_RUN)` counts 1". A runtime without kill points has no counter to read, so two testers write different tests. | should fix | Split it: with the point unarmed, `run` returns and `reached` is 1; built without kill points, `run` returns normally. |
| 5 | S0008, Interface (the first call's arguments) | `--permission-prompts none` is in neither the handover nor run-facts, and the drafter reports it unchecked against the pinned version (as are `--tools ""` and `--effort`). If the pinned `claude` rejects an unknown option, every real agent run ends `died`, while every criterion passes against the stand-in. `--permission-mode auto` also changes v1's behaviour: in print mode v1's `permissionMode: auto` had no effect (handover SI4, problem). | should fix | Check each flag against the pinned `claude --help` before S0008 starts, and drop any the pinned runtime lacks. Record the flags as a morning observation tied to F0010's preflight probe (ST5.3). List `--permission-mode auto` among the decisions as a change from v1. |
| 6 | S0008, Interface, end-reason rule; criteria 11, 13 and 16 | The rule checks the exit status first ("died when the exit status is not 0"), before `subtype` `error_max_budget_usd`. If the pinned `claude -p` exits non-zero on an error result, the budget resume never runs, the `budget` end reason never appears, and run-facts' "one resume for a quarter more" is lost. The tests cannot see this, because the stand-in exits as the tester chooses. | should fix | Decide the budget case on `subtype` whatever the exit status, or check the pinned runtime's exit status on a budget stop. Add a criterion with exit status 1 and `error_max_budget_usd`. |
| 7 | S0004, whole story (25 criteria) | It holds `run_process` (session, process-group kill, merged output, decoding), the error types, six git operations, two source searches, the marker rule and the shared fixtures with a four-file remote. That is a lot for the tester's $2 and the coder's $4 within a 60-minute lease. | should fix | Split `run_process` with its searches and markers (criteria 1 to 8) into its own story ahead of the git reading operations. |
| 8 | S0008, whole story (25 criteria) | It holds the argv, three state files, the JSON schema, JSON parsing, the end reasons, the resume with its added-up measures, a `time_limit` shared across both calls, `version()` and a search, plus a stand-in executable for the tester to build. Same budget risk as finding 7. | should fix | Move `version()` and the resume (criteria 13 to 17, 20 and 21) into a following story. |
| 9 | S0005, Interface rules on `checkout` | "Uncommitted changes that stand in the way is a `GitError` and leaves the current branch" has no criterion, and neither does "creates the local branch from it, tracking it". Intake treats a rule without its failing-side criterion as a question. | should fix | Add a criterion: with a local edit that the switch would overwrite, `checkout(other)` raises `GitError` and the branch and the edit stay. Either add one for the upstream or drop "tracking it". |
| 10 | S0009, criterion 16 against the `status` rule | The rule calls "any newly staged path" `"added"`. Criterion 16 says that "a file that is staged and then edited again" is `"modified"`. For a new file that is staged and then edited, the two contradict each other, so testers will pick different files. | should fix | Write "a tracked file that is changed, staged and then changed again is listed once, as `"modified"`", and add that a new file staged and then edited is listed once, as `"added"`. |
| 11 | S0010, criterion 2 against the `delete_remote_branch` rule | The rule says that `origin/<branch>` is gone after `"pushed"`, including when the branch was already gone from the remote. Criterion 2 says the call "changes nothing". With a stale remote-tracking ref in the checkout, which is the normal case after an earlier fetch, the two cannot both hold. | should fix | State it: when the branch is already gone, the result is `"pushed"`, the remote is unchanged, and a stale `origin/<branch>` is removed. |
| 12 | S0005 (decision 10), FEATURE decision 10 | Every commit's author and committer are fixed in code as `factory <factory@noreply.invalid>`, overriding the environment. Kept thing 18 lists "identity set" as a preflight item, and R25 puts the instance's settings in the environment. Neither the handover nor run-facts gives this address as v1's. The drafter flagged it for the audit. | should fix | Let the human decide. Either the identity is a `GitCli` constructor parameter filled from configuration by wiring (F0010), or the fixed identity is recorded as a decision that retires kept 18's "identity set" item. |
| 13 | S0004 (decision 7), FEATURE decision 7 | `GIT_CONFIG_GLOBAL` at the null device and `GIT_CONFIG_NOSYSTEM=1` also discard any credential helper or `http.extraHeader` that the image or the operator sets in global or system configuration. WE3.5 ("the factory's own pushes ... still work") and R33 ("git ... get[s] the token from the factory process only") then rely on credentials passing through environment variables (`GIT_CONFIG_COUNT`/`KEY`/`VALUE` or `GIT_ASKPASS`), which `GitCli` does inherit. Nothing says so, and F0010 may plan a global helper. | should fix | Add a sentence to S0004 and the feature: credentials reach git only through the factory process's environment (named mechanism), never through global or system configuration. Add a criterion that a `GIT_CONFIG_COUNT` entry in the process environment reaches git. |
| 14 | S0008, Interface rules | Some rules have no criterion: a state directory that cannot be written raises `AgentRuntimeError`; `version()` raises when it reaches its 30-second limit (untestable without a 30-second wait, because the limit is fixed); "no resume is started when nothing is left". Whether the state files are removed after an `AgentRuntimeError` is not said. | should fix | Add a criterion for an unwritable state directory (a file in its place). Make the version limit a constructor argument so it can be tested, or drop the rule. Say what happens to the files on `AgentRuntimeError`. |
| 15 | S0006, Tests paragraph against criterion 16 | "The only waiting in the tests is for a command that the `time_limit` kills", but criterion 16 runs a target of about 0.3 seconds that is not killed. | note | Allow the 0.3-second target in the Tests paragraph, as S0008 does. |
| 16 | S0004 criterion 5; S0006 criterion 9 | "A grandchild it started are killed" and "the `sleep` it started is gone" do not say how a test observes it, so testers will differ (a pid file, `ps`, `/proc`). | note | Name the method, for example: the target writes its child's pid to a file, and after the return `os.kill(pid, 0)` raises `ProcessLookupError`. |
| 17 | S0008, criterion 6 and the stand-in helper | The helper is described as recording "every file named in its arguments". The guard file is not an argument: it is named only inside the hooks file's command. As described, the stand-in cannot show the guard file's content. | note | Say that the stand-in also records the file named after `--settings` in the hook command, or that the test reads the guard path out of the recorded hooks file. |
| 18 | S0004 criterion 6; S0006 criterion 10 | The rules say "greater than zero" and "zero or less", but only zero is tested. | note | Add `timedelta(seconds=-1)` to each. |
| 19 | S0004, criterion 10 | `time_limit=timedelta(milliseconds=1)` assumes that `git rev-parse` never finishes within 1 ms. That is practically always true, but it is a timing assumption in a criterion. | note | Accept it, or use a stand-in `executable` that sleeps. |
| 20 | FEATURE decision 9; S0004, Assignment | Both ask the human to add a line to CLAUDE.md allowing the four markers in `process.py`. CLAUDE.md already holds exactly that exception ("The one exception, decided with the seed ..."). | note | Rewrite the decision and the precondition as already met. |
| 21 | FEATURE decision 3; S0002, Assignment | S0002 creates `identifiers`, `git` and `paths`, which the interface sheet gives to F0002-S0001 and F0001-S0004. The instruction that F0002-S0001 "must not create them again" lives only in F0001's text, not in the interface sheet. | note | Have the cross-check confirm that F0002-S0001's Interface says "adds to". |
| 22 | S0002, Assignment | It says that `HostingService` has "exactly the operations R10 lists", but R10 lists no lookup of a branch's open pull request, no draft/ready switch and no description write. These rest on R22 (the description as the one projection) and kept 11 (draft or ready). | note | Say "R10's operations plus those R22 and kept 11 need". |
| 23 | S0002 criterion 14; S0003 criteria 18 and 19; S0004 criterion 7 | The searches are narrower than their rules. The R7 search matches only `dict[str, Any]` and `Mapping[str, Any]` written that way (not `MutableMapping[str, Any]` or an alias). The R5 search checks `subprocess`, `os.system` and `os.popen` but not `os.exec*`, `os.spawn*` or `asyncio.create_subprocess_*` (ruff's S606 covers some of these). The SI2.1 search lists named HTTP libraries only. | note | Widen each search, or accept it as is and name what it leaves out. |
| 24 | FEATURE decisions 7, 11 and 13 (S0004, S0006, S0008) | These are defaults with no source in the inputs. A git `time_limit` of 5 minutes. `last_line` skipping `make:` lines, which changes the interface sheet's "last non-blank line". A resume budget of at least 0.50 (run-facts gives only "a quarter more"). A `FINISH_MESSAGE` that sends an unfinished agent to `question` instead of v1's `stuck`, so a budget stop now reaches the human instead of costing an attempt. | note | Keep them listed for the human. The `question` change in particular is a behaviour change from v1. |
| 25 | S0008, Interface (hooks file) | The hook command is the bare `factory-guard`. With "nothing inherited" and an environment without `PATH` (as in the Demo), the hook cannot start. Claude Code treats a hook that fails to start as non-blocking, so the guard fails open. | note | State that the request's environment must carry `PATH` (F0005 and F0010), or write the hook command with an absolute path that the runtime is given. |
| 26 | S0003, Assignment against FEATURE, Out of scope | S0003 says that building the `Repository` from the token is F0010. FEATURE says "F0002 onward (`factory.entry.wiring`), F0010 for the token". | note | Use FEATURE's wording in S0003. |
| 27 | S0003, Demo, first block | `PyGithubHostingService(Broken())` has no `owner`. The Demo works only if the constructor does not read `repository.owner`, which the Interface does not say. | note | Add to the rules: the constructor reads nothing from the repository. |
| 28 | S0003, `set_labels` rule (decision 5) | It reads the pull request's labels to keep the ones the factory does not own. R10 and decision 001 say that labels are "never read back". An internal read that decides nothing is arguably allowed, but it is the human's call. | note | Keep it listed for the human, or use add and remove calls that need no read. |
| 29 | S0009, Assignment | It says that nothing in S0010 depends on S0009, but S0010's Demo calls `status()`. The order still holds, because 0009 is lower than 0010. | note | Correct the sentence. |
| 30 | S0002, S0004 to S0007, S0011 (Tests) | Later testers extend `tests/conftest.py` and `tests/domain/test_errors.py`, which earlier stories' testers wrote. CLAUDE.md lists "change to a test you did not write" under "Not without asking", which may produce a question. | note | Say in each Tests paragraph that the file is extended with new tests and fixtures only, and that no existing test is changed. |
| 31 | S0004, S0005 (test helpers `run_git`, `HumanClone`) | Whether test helpers may import `subprocess` is not said. The Demos run git through `run_process`, and ruff's `S404` is not ignored under `tests/`. | note | State that test helpers start git through `factory.adapters.process.run_process`. |
| 32 | S0010, criterion 24 | "`GitCli` implements exactly these nineteen operations" leaves open whether a public helper or property on `GitCli` breaks it. | note | Write "`Git` has exactly these nineteen operations, and `GitCli` has each of them". |
| 33 | S0004, `GitError.output_tail` | The rule makes `output_tail` the command's whole output, while the name and the interface sheet suggest a tail. A large `fetch` output goes whole into the message. | note | Cap it (for example the last 30 lines, as `CheckResult`), or rename it. |
| 34 | S0006, criterion 23 (docs) | It uses "verdict", a v1 word that the glossary renames "recommendation". | note | Write "the only judgment" or "the only result". |
