# Audit of F0011-proof-and-documents, round 1

## Summary

- 36 findings: 7 blockers, 14 should fix and 15 notes, over `FEATURE.md` and the four drafts S0001 to S0004.
- Blockers: no scripted run ever reaches `agent-run`, because the helpers `completed` and `died` never set `ScriptedRun.kill`, which is the only way `FakeAgentRuntime` reaches the point (1). Three Demos pass `-q` on top of `pyproject.toml`'s `-q`, and pytest 9.1.1 at `-qq` prints no summary line (2). S0003 keeps the dropped stop `v1_work_item_found`, so `STOP_TABLE` fails at import (3).
- More blockers: in path 8 the attempts-cap question is expected one tick too early (4), and in path 13 the human answers before the question is posted, so the wait never ends (5). Four closed models have no criterion for a refused assignment, an unknown key or a refused `Literal` (6). S0004's word lists forbid text that earlier stories' docs criteria require, such as "no `--follow` mode" and v1's leftover file names (7).
- The should-fix findings are mostly scenario gaps. The `World` has no remote, no state directory and no installed agents. A module-scoped `run_case` sits over function-scoped fixtures. `start_story` names no file, and the fixture's backlog story keeps path 12's feature from ever becoming due. Three stop scenarios queue no run. `leak_writes` needs a branch that does not exist yet. Two test names break ruff's line length. S0004 has rules without criteria. S0002 is too large for the tester.
- Questionnaire 1 and decision 008 change S0001 (Q3: no run record; Q20: the wiring by name; Q28: the tick status) and S0003, `FEATURE.md` and S0004 (Q15 and 008: no v1 stop). Three names differ from what F0001 and F0002 built: the `kill` flag, F0002-S0006 and `PostKey`'s keyword arguments. The exact edits are in "Questionnaire answers to apply".
- Order, write paths, dependencies, the closing criteria and the criteria counts (23, 20, 16 and 19, all within 26) hold. No story needs Docker, root, network or real GitHub.
