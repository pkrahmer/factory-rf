# The operator guide's chapter "The machine"

## Description

An operator who has never seen v1.1's container must take a fresh Ubuntu 24.04 VM to a running `container` instance in under an hour of their own time with the operator guide alone (`planning/v1.2-plan.md`, F0043's goal). S0001 and S0003 left the sections *The stage image*, *The script* and *The service* in a chapter `## The machine` of `docs/operator-guide.md`; this story completes the chapter from the runbook (`planning/overnight/gcp-runbook-2026-10-24.md`) and the plan, and the documenter reads the whole chapter against the code once: GCP in numbered steps (the project and the budget alert, NAT and IAP, the VM with no service account and no external address, the data disk, the script and its second run, the secrets by hand, the image build, the first start, the board and the health over SSH, the rebuild after a merge); the same for any Ubuntu 24.04 VM with a spare disk, and what the script needs that `podman machine` and WSL 2 do not give; what the container can and cannot see; the costs with the plan's numbers; the metadata server; where the logs are. It also writes the decision-log entry of the machine. No code, no test but the one that pins the chapter, no image change; `make documents` passes. What stays: every sentence of the three earlier sections that is still true; the chapters of v1.1's image and container, which F0044 (the layers go) removes.

## Interface

None: nothing changes under `src/factory/`, in any test but the new module, under `vm/`, `image/`, `template/` or `claude/`. The documenter changes `docs/operator-guide.md`, `docs/decisions.md`, `docs/project-guide/README.md` (if a section name of the guide index must follow) and `README.md`, as the docs criterion says. The tester writes `tests/test_documents_machine.py`, which reads `docs/operator-guide.md` and `docs/decisions.md` as `tests/domain/test_documents_guide_files.py` reads documents and pins criteria 1 to 4.

## Acceptance criteria

1. `docs/operator-guide.md` has one chapter `## The machine`, placed before `## The machine's image`, whose `###` sections are exactly, in this order: *What it is*, *The stage image*, *The script*, *The service*, *On GCP, step by step*, *On any Ubuntu 24.04 VM*, *What the container can and cannot see*, *The costs*, *The metadata server*, *Where the logs are*, *The rebuild after a merge*.
2. *On GCP, step by step* is a numbered list of at least ten items that names, in this order, `gcloud billing budgets create` with `120`, `gcloud compute routers nats create`, `--tunnel-through-iap`, `--no-service-account`, `--no-address`, `gcloud compute disks create`, `gcloud compute scp`, `vm/setup.sh`, `/home/factory/.secrets`, `podman build -f vm/Dockerfile`, `systemctl start factory@vm`, `factory-watch` and `factory-health --state-directory`; *The rebuild after a merge* names, in this order, `git pull`, `uv sync --frozen --no-dev`, `podman build`, `image-id`, `vm/setup.sh` and `systemctl restart factory@vm`.
3. The chapter names (rows of one parametrized test, one per phrase): `e2-standard-2`, `europe-west3`, `pd-balanced`, `50`, `$120`, `169.254.169.254`, `Metadata-Flavor`, `journalctl -u factory@vm`, `/srv/factory/vm/state/factory.log`, `stage environment:`, `zfs allow`, `--sudoers`, `--userns=keep-id`, `podman machine`, `WSL`, `hosting-token`, `claude-token`, `anthropic-api-key`, `Cloud NAT`; *The costs* holds a table with one row each for the VM, the disk and NAT and a sentence on a stopped VM; and the chapter holds the phrases `second user` and `sudo` only in sentences that say the machine has none (each occurrence's line holds `no ` or `without` or `none`).
4. `docs/decisions.md` has one section `## The factory runs on the host, and the stage image carries the tools alone` that names `2026-10-24`, `planning/v1.2-plan.md`, `F0043`, `systemd`, `factory@`, `zfs allow`, `sudoers`, `/etc/factory/claude`, `FACTORY_IMAGE_ID_FILE` and `F0044`; and `README.md` names `vm/setup.sh` once in a sentence for the newcomer that points to the chapter.
5. Nothing under `src/`, `tests/` (but the one new test module), `vm/`, `image/`, `template/` or `claude/` changes; the coder ends with an entry saying so.
6. `make check` stays green.
7. docs: the documenter writes the chapter as criteria 1 to 3 say, from the runbook and the plan, with these contents: *What it is*: the host (the factory as `factory@<instance>` under the user `factory`, the hosting token on the host and nowhere else), the dataset (`<pool>/factory/<instance>` at `/srv/factory/<instance>/work`, `/work` in every container, its base `@base`), the container (the stage image, `--rm`, `--userns=keep-id`, `--timeout`), one user and no second one, no `sudo` but the optional `zfs` fallback, and the layout of `/srv/factory/<instance>` (`work`, `repo`, `state`, `factory`, `tools`, `factory.env`, `image-id`, `askpass`); *On GCP, step by step*: the runbook's sections 1 to 4 as numbered steps with their commands, then the script's first run, the three secrets placed by hand as `factory` (`install -m 0600 -o factory -g factory`, never pasted into a chat or an agent's prompt), the script's second run, the image build as `factory` (`podman build -f vm/Dockerfile -t factory-stage:vm --build-arg FACTORY_IMAGE=<ref> /srv/factory/vm/factory`), the first start, the board (`factory-watch` with the environment file loaded: `set -a; . /srv/factory/vm/factory.env; set +a`) and the health (`factory-health --state-directory /srv/factory/vm/state`), and `gcloud compute instances stop` when the machine is not used; *On any Ubuntu 24.04 VM*: the same from the script on, what the script needs (a kernel with the ZFS module, a spare block device, rootless Podman with a sub-id range for `factory`, outbound network for apt, npm, GitHub and the Anthropic API), and that `podman machine`, WSL 2 and the workplace's Podman Desktop are not hosts for it (the plan's question 7); *What the container can and cannot see*: the dataset at `/work` with the checkout and the agent's home, the read-only mounts (the host repository's `.git` at `/upstream` in the sync container, the login and instructions files at their paths), the network (the API, npm, GitHub through NAT), and not the hosting token, the host's files, the next stage, or anything of the metadata server worth having; *The costs*: the plan's numbers (`e2-standard-2` about $50 to $55 a month, `e2-standard-4` about $100, the 50 GB `pd-balanced` disk about $5, Cloud NAT about $1 a month plus traffic, the budget alert at $120 with its three thresholds), a stopped VM costs its disks; *The metadata server*: `169.254.169.254`, what a container gets from it with `--no-service-account --no-scopes` (instance metadata, no token), and the `Metadata-Flavor: Google` header; *Where the logs are*: `journalctl -u factory@vm` (what `factory-run` prints), `/srv/factory/vm/state/factory.log` with the `stage environment:` lines and how to read the plan's measures from them, `health.json` through `factory-health`, and `podman ps` for a running stage container; *The rebuild after a merge*: as `factory`, `git -C /srv/factory/vm/factory pull --ff-only` (or `git fetch --tags` and `git checkout <tag>` for a tagged ref), `uv sync --frozen --no-dev` with the tools' `uv`, `podman build ...`, a new uuid into `/srv/factory/vm/image-id` (`cat /proc/sys/kernel/random/uuid > /srv/factory/vm/image-id`), `sudo sh vm/setup.sh <the same arguments>` when `vm/Dockerfile`'s pins changed (it rewrites the environment file and reports the rest found), then `sudo systemctl restart factory@vm`. The documenter reads *The stage image*, *The script* and *The service* against `vm/Dockerfile`, `vm/setup.sh` and `vm/factory.service` and corrects any sentence that is no longer true. `docs/decisions.md`: the entry of criterion 4, dated 2026-10-24, with the human's decisions 1, 3, 6 and 8 of the plan, the reasons (one user, the token on the host, the delegation first and the `sudoers` fallback second, the image without the factory so that the factory's code and the tools change apart, the identity file the operator renews), what was rejected (the factory in a container with the podman socket, the factory as root, the stage container pushing), and that F0044 removes the Docker path. `README.md`: one sentence for the newcomer that an instance of v1.2 runs on a VM prepared by `vm/setup.sh`, pointing to the chapter. `docs/project-guide/README.md`: none, unless a guide file names a chapter of the operator guide that moved. `make documents` ends with `documents ok`.
