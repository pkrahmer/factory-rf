# The code says what it does, once

## Goal

The read-only review `planning/overnight/mess-scan-2026-10-20.md` found code that says something other than what it does, and code written twice. A docstring of `Tick` (`src/factory/application/tick.py`) says "nothing local is read", though every tick reads the instance's health file and its stop records and publishes them; its `run` docstring leaves the publication out. `CheckoutPreparer.prepare` (`src/factory/application/scheduler.py`) is typed `-> bool` and documented "always `True`", and its one caller ignores the value: a reader looks for a `False` that does not exist. The two agent runtimes (`claude_runtime.py`, `opencode_runtime.py`) each read the end of a call in the same lines, with the same comment: the kill by the runtime's own `timeout` and then the refusals of `sudo`, the write guard's wrapper and the login shell, and each writes the state-directory error text itself; a fix to that fault path in one runtime only is the likely next bug, and F0029 and F0030 keep working on it. Twenty-nine test modules hold copies of shared helpers: sixteen copy the `definition` fixture as `_definition`, five copy `log_support.log_lines`, five copy `stage_run_support.pushed_state` or its reading, and others copy fixtures of `tests/conftest.py` or of each other; the guard `tests/test_shared_fixtures.py` matches only the fixture's own spelling and misses all of them. `NOT_YET_HANDLED` (`src/factory/entry/wiring.py`) has been `()` since every event kind got its handler, and five tests compare it with an empty set under names that claim more. This feature fixes each at its cause: the shared reading moves into `factory.adapters.agent_launch`, the test copies give way to one shared place each with a guard that finds them by their body, the docstrings and the return type say what the code does, and the empty constant goes. It is for the agents, who read docstrings and test helpers as the design, and for the human, who reviews one copy instead of five. Each finding was checked against the code of 2026-10-20 before it was drafted. Done when every story below is merged and `make check` is green.

## Decisions taken for the human

1. **The cause of the runtimes' copy.** F0020 moved the words, rules, refusal readers and the resume share into `agent_launch` (the decision log's *What the agent runtimes share lies in one module*), but the sequence that uses them at the end of a call stayed in each runtime's `_call`, with the same comment twice: read the own `timeout`'s kill as the time limit first, then read the refusals with that reading. The order matters (a call that printed a reply but was killed is read for refusals), so it moves whole into one function, `read_call_end`. The state-directory error text joins it as `state_directory_error` (S0001).
2. **The process calls stay in the runtimes.** The review proposed moving `_start`, `_request_of`, `_remove_temporary_folder` and `version` into `agent_launch` as well. The decision log says that `agent_launch` "builds words and texts and imports no process module", `tests/test_agent_launch_search.py` pins it, and the tests set `run_process`, `SHELL_EXECUTABLE` and `CLEANUP_TIME_LIMIT` on `claude_runtime` (`tests/conftest.py`'s `recorder`, `tests/adapters/test_claude_runtime_confinement.py`). Moving them would undo that decision and change those tests; the copies left are each a few lines without a fault path of their own. `read_call_end` takes the process's fields, not a `ProcessResult`, so `agent_launch` still imports nothing of `factory.adapters.process` (S0001).
3. **The state directory stays as it is.** The review's U1: `ClaudeCodeRuntime` creates its state directory, `OpencodeRuntime` refuses a missing one, and `tests/adapters/test_opencode_runtime.py` pins the refusal (row `state-missing`). The image creates `/state/runs`, so production never meets the difference, and `docs/project-guide/agents.md` already documents the opencode side. Making them alike would change a test another story wrote for no change in production. The docs criterion records the difference as deliberate. If the human wants them alike, S0001 gains one criterion and a leave for that row (S0001).
4. **No structural test of the runtimes' source.** That neither runtime keeps its own call of `killed_at_limit` or `call_refusal` is a rule of S0001's Interface for the reviewer, not a test: a test that reads `src/` would need a `--deselect` line in `[tool.mutmut]`, a change of the human's, for a rule the review sees at once (S0001).
5. **One shared place per helper, found by its body.** The guards of S0002 and S0003 find a copy by its body or its parameters, not by its name, so the next copy under a new name is found too. Only copies that do the same as the shared helper move; a variant with other parameters or another body stays where it is (see *Out of scope*), because changing what it does is beyond the standing leave. `_definition` gets a function, `definition_support.pipeline_definition`, beside the `definition` fixture, because its callers call it inside helpers that take no fixtures. `_error_posts` moves without a guard: `test_lookups.py` has a helper of the same name and parameters that compares the whole key, so a guard by parameters would find it, and one by body would find `tests/test_stop_table.py`'s (S0002, S0003).
6. **The human's leave for S0004**: the tester changes `assert <preparer>.prepare() is True` (or `prepared = ...prepare()` and `assert prepared is True`) into a call as a statement in these tests, each keeping its name and every other line: `tests/application/test_nested_repositories.py::test_the_preparer_removes_the_nested_repositories_of_a_kept_checkout` and `::test_a_missing_checkout_is_cloned_without_a_search`; `tests/application/test_checkout_preparer_seal.py::test_a_missing_checkout_is_cloned_and_sealed`, `::test_a_sealed_checkout_is_kept_and_sealed_again_without_a_log_line` and `::test_a_checkout_whose_git_folder_fails_the_check_is_removed_and_cloned_again`; `tests/application/test_scheduler.py::test_a_missing_checkout_is_cloned_and_cloned_again_after_removal` and `::test_an_existing_clone_is_kept_without_calling_git`. Without it `mypy --strict` refuses the value of a call typed `-> None` (`CLAUDE.md`, *Tests*). `tests/application/test_checkout_preparer_seal.py`'s `prepared = waiter.prepare()` reads `RepositoryWaiter.prepare`, which stays `-> bool`, and is not changed (S0004).
7. **The human's leave for S0005**, each test's other lines unchanged: in `tests/entry/test_wiring_acceptance.py::test_every_kind_has_a_handler_and_acceptance_due_opens_the_acceptance`, the line `assert NOT_YET_HANDLED == ()` goes (the test keeps `set(handlers) == set(get_args(EventKind))` and `unhandled_kinds(handlers) == []`, which already catch a kind without a handler). `tests/entry/test_wiring_handlers.py::test_the_kinds_without_a_handler_are_exactly_those_not_yet_handled` and `tests/entry/test_wiring_human_handlers.py::test_the_kinds_not_yet_handled_are_exactly_the_kinds_without_a_handler` are removed: with the constant gone they repeat the acceptance test. `tests/entry/test_wiring_recovery.py::test_crash_is_handled_and_the_kinds_not_yet_handled_are_the_kinds_without_a_handler` becomes `test_crash_is_handled`, and `tests/entry/test_wiring_recovery_expired.py::test_expired_shares_the_crash_handler_and_is_no_longer_listed_as_unhandled` becomes `test_expired_shares_the_crash_handler`, each without its `NOT_YET_HANDLED` lines. `unhandled_kinds` stays: the acceptance test and `tests/application/test_dispatcher.py` use it (S0005).
8. **Open, for the human: the six optional `Boundaries` fields (the review's A3).** The comment on `settings`, `disk`, `disk_records`, `stop_records`, `waiter` and `result_records` says they are optional "so that every construction written before them stays valid"; the one production construction (`build_boundaries`) sets all six, and the application branches on `None` in a dozen places. Checked on 2026-10-20: the wiring tests already assert each of the six on the built boundaries (`tests/entry/test_wiring_boundaries.py` for `settings` and `disk`, `test_wiring_known_results.py`, `test_wiring_record_logs.py`, `test_wiring_stop_records.py`, `test_wiring_waiter.py`), so the review's cheap alternative is in place, and a dropped field fails a test. Options: (a) leave it (recommended: the risk the review names is covered); (b) reword the comment only, to "Optional so that a test can leave a feature out; the wiring sets all six, and the wiring tests pin each": one line, which the human may add to S0004 before it starts; (c) make the six required and give the `boundaries` fixture real collaborators: about 25 tests replace these fields today, and `CLAUDE.md`'s own example (`replace(b, disk=None)`) uses the `None`; a feature of its own, with leaves for every one of them.
9. **Open, for the human: the stop records file on `main` (the review's B2).** `StopPublisher.publish` (`src/factory/application/stops.py`) writes `factory/stops.jsonl` with `path.write_text` itself, the one file write in `factory.application`, and formats it with `factory.domain.stops.stop_records_text`, a second codec of the line that `JsonLinesRecordLog` writes for the local copy. Checked on 2026-10-20: it holds, but `StopRecord` has no free text (event, scope, reason, time, instance), so the two codecs cannot disagree today, and the domain functions are pure. A fix needs a new writer interface and a new `Boundaries` collaborator, which meets decision 8's question. Options: (a) leave it until decision 8 is settled (recommended); (b) a `StopRecordsFile` interface with a write of the whole text, its adapter and its fake, as a story after decision 8; (c) publish through a second `RecordLog[StopRecord]` on the checkout's file, which also drops `stop_records_text` and `parse_stop_records`.
10. **The order against the other drafts.** S0001 changes only `src/factory/adapters/{agent_launch,claude_runtime,opencode_runtime}.py` and adds a test module; F0029-S0002 changes the time limits of the runtimes' tests and F0030 the kill in `process.py`, both on the fault path S0001 reads, so S0001 starts after both, and its criterion 4 runs their tests as they then stand. S0003 adds two fixtures to `tests/conftest.py`, where F0033-S0001 adds a `pytest_configure` hook: S0003 starts after F0033. F0032 (it removes `check_mutants` and `domain.mutants`), F0036 (the protected paths) and F0037 (the record log) touch no file of this feature's stories. S0002 to S0005 touch none of F0029's, F0030's, F0032's or F0036's files.
