# Smaller items of the candidates list

## Goal

`planning/v1.2-candidates.md` collects small findings that waited for v1.2: six items noted on 2026-10-21 from the acceptances of F0038 (the documents say what is true today), F0039 (the code says what it does once) and F0040 (agent code never runs with the factory's rights), and three items the human added on 2026-10-24 for this feature. F0042 (the stage environment behind one interface), F0043 (the machine and the stage image) and F0044 (the layers go) remove most of what those findings were about; this feature, the fourth and last of v1.2 (`planning/v1.2-plan.md`, section "F0045"), checks each item against the code as F0044 leaves it and builds what is left. It is built by the instance `vm` on the VM with the `container` stage environment, after F0044 is accepted. It is for the human, who runs the factory on a VM that costs money while it runs, and for every later reader of the code and the tests. When it is done: a slip the smoke tester finds in a document goes straight to the docs stage; the stall reason `left_branch`, which nothing can cause any more, is gone with the records contract's next major, `4.0`; the agent files' folder and the image identity file are settings without a v1.1 default; the process result no longer carries a field no caller reads; the factory can power its VM off after an idle stretch, an option that is off by default, with the one right it needs given by `vm/setup.sh` only when it is used; and no test module imports another test module. Done when every story below is merged and `make check` is green.

## Decisions taken for the human

1. **The split and the order** (all stories). One story per item that stays, except the idle shutdown, which is two: the factory's part (S0005: the setting, the interface, the wrapper, the counter, the wiring; testable on Windows and in the container with a manual clock and a stand-in `sudo`) and the machine's part (S0006: the script's option, the right, the environment file's line), because each is a coder's forty minutes and the second is pinned by text tests of F0043-S0003's kind. S0001 first, so that the six stories after it profit from the short way of a slip in a document; S0007 last, so that its guard holds for every test this feature wrote. Options: A, this (taken); B, the idle shutdown as one story (two rule sets and two documents in one coder's run); C, S0007 first (the later stories' testers might import a test module again before the guard exists, which the guard would then refuse, so A and C end the same, but C makes the later testers obey a rule the candidates list asked for first).
2. **`UV_LINK_MODE=copy` falls with F0043-S0001 and F0044-S0008** (no story). The finding (F0040-A0002, note 4a) was that `sudo ... env -i` drops the image's `UV_LINK_MODE=copy`, so uv printed its hard-link warning into the agent's context. On a `container` instance the call is `podman run` with `--env` entries for the request's environment only (F0042-S0003, `PodmanRuns.launch`), so the container keeps the stage image's own `ENV`, and F0043-S0001's criterion 6 pins `ENV UV_LINK_MODE=copy` in `vm/Dockerfile`; after F0044-S0008 no agent runs on the host, and F0044-S0005 removes `project_command_environment`, the host's own setting of it. Nothing is left to change.
3. **`leftovers_command()` without `-B` falls with F0044-S0003** (no story): that story removes `leftovers_command`, `LEFTOVERS_MODULE` and the program `factory.entry.leftovers` whole (its criteria 1 and 2).
4. **The "Open" of the entry on the kill under `sudo` falls with F0044-S0005** (no story). The entry "The agent's own `timeout` kills a run under `sudo` at its time limit" (F0012-S0024) ends with "Open: observed for real only at the first start." F0044-S0005's docs criterion closes that entry with the line "Replaced by the throwaway container, v1.2 F0044-S0005", which ends the open point with the mechanism it was about; F0040-A0002's note 5 found the observation itself recorded in a later entry. Nothing is left to write.
5. **`output_abandoned` goes, the drain stays** (S0004). The field is read by no caller under `src/factory` (F0040-A0002, note 4c; it is accepted as dead code in `security/duplicates-baseline.txt`). After F0044 the host starts only git, `zfs`, `podman` and `make` (the suite's), whose pipes close with their process; a field that only tests read is the "said twice" F0039 removed elsewhere. The bounded read after the child's end (`PIPE_DRAIN`) is behaviour and stays exactly as it is. Options: A, the field goes (taken); B, a caller logs it (`ContainerMakeCommands` or the runtimes would write a line no stop and no operator reads); C, keep it as it is (the baseline keeps a standing finding).
6. **A slip in a document goes from the smoke test straight to `docs`** (S0001; the human's change 1). The long way (F0038-A0001, note 8) was smoke test, then `doing` (the coder may not write `docs/`), then review, then docs, then the smoke test again: four extra runs each in F0038-S0007 and S0009. The decision rules already treat every `next` entry after the first as a rework counted against the stage's `round_cap` (`factory.domain.decisions.decide`), so adding `docs` to the smoke test's `next` needs no code: the smoke tester ends with `docs` when every finding is a slip in a document the documenter writes and the code does what the work item says, else with `doing` as today. The candidates list names "a finding the reviewer marks as docs-only", but no reviewer runs after the smoke test; the smoke tester is the one who sees the finding. Options: A, this (taken); B, the coder passes a docs-only finding on with `review` and the reviewer with `docs` (the long way, shortened by nothing); C, a factory rule that reads the findings' paths (a new mechanism for a judgement an agent already makes).
7. **The rule for the tests' imports: no module imports a test module** (S0007). The candidates list proposes "shared test code lives only in `*_support.py` modules". Today shared code also lives in modules named otherwise (`human_clone.py`, `recording_log.py`, `source_search.py`, `shipped_agents.py`, `time_limits.py`, `observing_runtime.py` and others), and renaming them would change some hundred imports for no gain. So the rule is the one that removes the problem: no module under `tests/` imports a module whose file name begins with `test_`, in any of the three forms (`from <x>.test_y import ...`, `import <x>.test_y`, `from <x> import test_y`); what one test module imports from another moves into a support module, and a new support module is named `*_support.py`. The guard is `tests/test_shared_imports.py`, beside the six `tests/test_shared_*.py` that guard the shared helpers today. On 2026-10-24 seventy-three such import lines exist (`tests/test_time_limits.py` among them, which reads four test modules' wait constants; those constants move too); many go with the modules F0044 deletes (`tests/adapters/test_claude_runtime_os_user.py` alone is imported by sixteen modules), so S0007's pre-check counts them again on `main` after F0044. Options: A, this (taken); B, the `*_support.py` rule of the candidates list, with every shared module renamed.
8. **What idle means** (S0005; the human's open point, decided as proposed). An iteration of the loop is idle when its tick ran, ended at no repository stop, and dispatched the evaluation's `idle` event. That holds when nothing can be started, when the first waiting work item waits for the human (an approval, a posted question: the lease is not held then, as the candidates list proposes), and when a claim is held by another instance (that instance is running; after the cut-over of the plan only `vm` runs). It does not hold for a tick that ended at a repository stop or a machine stop, or that handled any other event (a capped or failing event included): a stop waits for a fix the operator may make on the machine itself, so the machine stays up. An iteration that ran no tick (the repository waiter's wait, a failed iteration) neither counts nor ends the stretch; the machine is powered off only right after an idle tick, when the stretch since the last tick that was not idle (or since the instance started) has lasted at least the limit. Options: A, this (taken); B, every iteration without activity (`activity` false) counts, stops included (the machine could power off while the operator fixes a low disk); C, a stage waiting for the human does not count (a story waiting overnight for its merge would keep the VM running all night, which is the cost the option exists to save).
9. **The right is one `sudoers` line for `/usr/bin/systemctl poweroff`, and the wrapper runs `sudo -n /usr/bin/systemctl poweroff`** (S0005, S0006). It is the way F0043's decision 7 gave the `zfs` fallback its rights: one file under `/etc/sudoers.d/`, mode `0440`, checked with `visudo -cf`, exactly one command with its argument, and `sudo` and `visudo` are on every Ubuntu 24.04. The script writes it only with `--idle-shutdown` and removes it on a run without the option, so the right exists exactly while the option is in use; the factory's setting comes from the same run (the environment file's line), so the two cannot drift. Options: A, this (taken); B, a polkit rule for `org.freedesktop.login1.power-off` and a plain `systemctl poweroff` (no `sudo` in the factory, but whether `polkitd` is installed on Google's Ubuntu image was not checked, and the rule language is JavaScript); C, the factory as root (rejected by the plan).
10. **A failed power-off is a log line, not a stop** (S0005). When the wrapper fails (no right, `sudo` missing, its time limit), the factory logs one line that begins `idle shutdown: ` and names the fault, does not raise, and starts a new stretch, so it tries again only after another full limit. A stop would keep a machine running that the operator meant to save, and stop no work. No preflight item checks the right: the option is off by default, and the log line says what is missing.
11. **The guide describes the start, not a script** (S0005). Starting again is outside the factory: the human runs `gcloud compute instances start factory-vm --zone europe-west3-a`, or sets up a GCP instance schedule that only starts the VM (the factory powers it off itself), by hand. `docs/operator-guide.md`, `## The machine`, *The idle shutdown*, says both and that a merge, a close or an answer while the VM is off is seen at the first tick after it starts again (open question for the human: whether the runbook gains the schedule's commands; this feature writes only the guide).
12. **The option is off by default and needs no switch of the environment** (S0005, S0006). Unset, blank or `0` means off; after F0044 only the container environment exists and the Docker path is gone, so "never on `inline`/Docker" holds by construction; an instance off the VM that sets the option fails to power off (decision 10) and runs on.
13. **`left_branch` goes with the records contract `4.0`** (S0002; F0044 decision 29 (b)). Removing a value of `StallReason` narrows the work item and acceptance states, a change that can break a reader, so the major rises after F0044's `3.0` (F0044-S0006). No record on `main` holds the value (checked on 2026-10-24: only story texts name it). On a `container` instance the agent works on the dataset and cannot move the host's branch, so the check after the agent (`git status` of the host's checkout against the work item's branch) can never fire and goes with the reason; the stall service still brings the checkout back to the branch before it takes, which S0002 does not touch.
14. **The two defaults become required settings, not the VM's paths** (S0003; F0044 decision 29 (c)). Both paths belong to the machine: `vm/setup.sh` writes them into the environment file (F0043-S0003: `FACTORY_IMAGE_ID_FILE=/srv/factory/<instance>/image-id`, `FACTORY_CLAUDE_HOME=/srv/factory/<instance>/factory/claude`), so `vm` is unaffected. A default in `factory.domain.settings` would put one machine's layout into the domain, and a wrong default fails late and quietly (the preflight's `agents` item finds no agents, or the image identity file is missing), while a required setting stops the start with the stop of invalid settings naming the variable. So `read_settings` refuses a missing or blank `FACTORY_CLAUDE_HOME`, and, when it is given a reader of the image identity (`factory-run`, `factory-watch`), a missing or blank `FACTORY_IMAGE_ID_FILE`; each refuses a relative path; `$HOME/.claude`, `/home/agent/.claude` and `/opt/factory/image-id` are never read. This also closes the "Open" of the entry "The image identity is read from a file the image build generates" (a blank variable fell back to the default path). The model `InstanceSettings` keeps the default of its field `agent_home`, because only the suite builds settings without `read_settings` (thirty-two test modules) and no instance can reach it. Options: A, this (taken); B, the VM's paths as defaults, built from `FACTORY_INSTANCE`; C, A and the model's field required too (thirty-two test modules change for no behaviour of an instance).
