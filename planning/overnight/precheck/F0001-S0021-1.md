## Facts checked

- **Criterion 1 against `git check-ref-format --branch`.** Git refuses all 18 values: `HEAD`, `^main`, `main~1`, `ma?n`, `ma[in`, `ma\in`, `ma in`, `a<TAB>b`, `a..b`, `a@{1}`, `/x`, `x/`, `a//b`, `x.`, `feature/.x`, `x.lock` and `feature/x.lock/y`, all as the draft says, and `@` as described below.
  - **`@`** is the one disagreement. Git accepts it (it prints `@`), and the draft refuses it on purpose ("and also `HEAD` and `@`").
  - **Criterion 2.** Git refuses `x*y`, `""`, `-x`, `:main` and `main:other`. It accepts `+main`, which decision 22 refuses on purpose.
  - **Other values I tried.** Git also refuses `.x`, `a\x1fb`, `a\x7fb` and `@{`. It accepts `feature/HEAD`, `HEAD-x`, `x.lockfile`, `x.lock.y`, `a.b`, `feature/-x`, `a{b`, `ä`, `a/@/b`, `@x`, `x@` and `refs/heads/main`. The draft's rules give the same answer for every one of these.
  - **Version.** On git 2.48.1 `HEAD` is refused with "fatal: 'HEAD' is not a valid branch name". The acceptance report says 2.39.5 refuses it too.
- **Criterion 3 against git.** Git accepts all six values, `main`, `work-item/F0001-S0001`, `feature/x`, `a+b`, `a@b` and `release-1.2`, each unchanged.
- **Criterion 2 is already met.** S0020's code refuses `"*" in value`, so `x*y` is a `ValueError` today, and so are `""`, `-x`, `+main`, `:main` and `main:other`. The criterion claims no change. It pins the acceptance's surviving mutant (`"*" in value` → `endswith("*")`). Its test will pass before the build, like S0020's criterion 8. That is fine.
- **Criterion 8 against real git.** `git push --porcelain --set-upstream origin refs/heads/work-item/F0001-S0001` exits 0 and prints `*\trefs/heads/…:refs/heads/…\t[new branch]`. It writes `branch.<b>.remote origin` and `branch.<b>.merge refs/heads/<b>`, and `git rev-parse --abbrev-ref 'work-item/F0001-S0001@{upstream}'` prints `origin/work-item/F0001-S0001`. The tracking ref equals the local commit. The porcelain ref line has the same form as before, so `_is_rejected` still works. The criterion passes today and after the build, so it pins behaviour.
- **Criterion 9 against real git.** `git push --porcelain origin --delete refs/heads/keep` exits 0 (`-\t:refs/heads/keep\t[deleted]`). The remote has no `keep`, and git itself removes `refs/remotes/origin/keep` from the checkout.
- **The "already gone is `pushed`" rule.** It still holds, but for a new reason, and `ALREADY_DELETED_MARKER` no longer matches anything:
  - Unqualified (today): `git push origin --delete gone` exits 1 with "error: unable to delete 'gone': remote ref does not exist". That is the marker.
  - Qualified: `git push --porcelain origin --delete refs/heads/gone` exits 0. The remote warns "remote: warning: deleting a non-existent ref", and git removes the stale `origin/gone` itself.
  - Why: git prints "remote ref does not exist" only for a destination it cannot resolve, and a name starting with `refs/` always resolves.
  - So the outcome is `pushed` through exit 0. The existing test `test_delete_remote_branch_already_gone_is_pushed_and_drops_the_stale_tracking_ref` passes against the simulated build.
  - `git update-ref -d` of a tracking ref that does not exist exits 0, so the cleanup line in `delete_remote_branch` is harmless when git already removed the ref (criterion 7's `origin/v1` never existed).
  - The marker check and the guide's sentence about git's `remote ref does not exist` become dead and stale. This is recommended edit 3; no role is likely to stop on it.
- **Criterion 6 against real git.** With only a local tag `v1`:
  - Qualified: `git push --porcelain --set-upstream origin refs/heads/v1` prints "error: src refspec refs/heads/v1 does not match any" and "error: failed to push some refs", and exits 1. There is no `!` ref line and the exit is not 128, so today's `_failed_push` raises `GitError`, not `"rejected"` or `"unreachable"`. The remote has neither `refs/heads/v1` nor `refs/tags/v1`.
  - Today's unqualified form pushes `refs/tags/v1:refs/tags/v1 [new tag]` and exits 0, so the test is red today for the right reason.
  - `refs/heads/HEAD` fails the same way (exit 1).
- **Criterion 7 against real git.** With the tag `v1` on the remote and no branch `v1`, `git push --porcelain origin --delete refs/heads/v1` exits 0 ("deleting a non-existent ref"), and `refs/tags/v1` is still there at the same object. Today's code deletes the tag, so the test is red today.
- **Existing tests.** I ran `tests/domain/test_git.py`, `tests/adapters/test_git_cli_{arguments,branches,writing}.py` and `tests/test_human_clone.py` twice, against today's code and against the simulated build.
