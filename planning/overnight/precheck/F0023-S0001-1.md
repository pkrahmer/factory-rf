## Points for the human, with recommended answers

1. Literal removal (edit 1): (a) a row of root files that only a literal removal passes; (b) drop the sentence. Recommended: (a). With plain pathspecs `git rm --cached -- "a*b.md" ":x.md"` removed `a*b.md`, `aXb.md` and `x.md`, and kept `:x.md` (seen in v1.1's image, git 2.39.5); the literal form removed exactly the two.
2. The fault order (edit 2): (a) two more rows in criterion 7; (b) drop the order clauses. Recommended: (a). The prototype gives `project command check: not_read /b/* must be a path pattern inside the checkout; project command check: not_read /a/* must be a path pattern inside the checkout`, and `tool path x: must be <folder>/* or ~/<folder>/*; project command check: not_read /a/* must be a path pattern inside the checkout`.
3. The copied index is more than speed (edit 3): a tracked file that a later `.gitignore` matches stays in every commit, and an index that started empty would leave it out of the tree. The key would then miss a file the command may read, so a change of it would reuse a stale pass. (a) say so in the Interface and add a row; (b) as drafted. Recommended: (a). Today no tracked file of factory-rf is ignored (seen), so this guards a future case.
4. The second copy of `is_inside_checkout` (edit 4): (a) move `is_inside_checkout` into `factory.domain.pipeline_definition` beside `PARENT_SEGMENT`, and let `write_paths` import it from there (its importers keep working); (b) accept the copy. Recommended: (a).
5. Sizing: no split. Four small source changes, regenerated schemas, four new test modules and three one-line test changes: well within the coder's 40 minutes and a few dollars.
