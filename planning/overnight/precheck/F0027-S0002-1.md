# Pre-check F0027-S0002, round 1: the agent runtimes end the agent's leftover processes after every call

I checked the story against v1.1's roles and forms, `CLAUDE.md` and `factory/pipeline.yml`. On the code side I read `src/factory/adapters/agent_launch.py`, `claude_runtime.py`, `opencode_runtime.py` and `process.py`, and `src/factory/entry/wiring.py`, including the version that F0020-S0008 is changing while I read: `build_boundaries` now builds `OpencodeRuntime` for `agent_runtime == "opencode"`. On the test side I read the wiring tests that run a call (`tests/entry/test_wiring_*.py`) and the stand-ins (`tests/adapters/claude_stand_in.py`, `opencode_stand_in.py`, `test_claude_runtime_os_user.py`, `test_claude_runtime_confinement.py`).

## What I ran

**Prototype.** I built a minimal version of the story in the temporary folder:

- `Starters.leftovers`;
- `leftovers_due`, `leftovers_launch` and `leftovers_fault`;
- the program after the call in `ClaudeCodeRuntime._call`, before the temporary folder's removal, with its fault raised after the refusal check;
- `leftovers_command()`.

**The whole suite** ran in a throwaway container of v1.1's image, together with the S0001 and S0003 prototypes. No earlier runtime or wiring test changed: every existing runtime is built without `leftovers`. That confirms decision 16 for this story.

**Smoke tests** ran as the factory user, with `python` in place of `uv run -q python`. Both blocks print exactly their `Expect:` lines:

- block 1: `smoke-other 0 completed | run in work; program --user smoke-other in /`, then the fault line, then `own 1 completed | run in work`;
- block 2: `True`.

Neither block runs the real program: block 1 passes a stand-in as `leftovers`, and block 2 only builds the list.

**`sudo` and the time limit, in a throwaway container.** As the factory user I started `sudo -n -u agent -- sleep 60` in a new session and called `os.killpg` on its group.

- The call succeeded and `sudo` died: its real uid is the factory's.
- The agent's `sleep` lived on with parent 1.

So at the program's 30-second limit `run_process` kills `sudo` and then waits in `communicate()` until the program closes its pipes. The real bound is the program's own 50 rounds, not the 30 s, which is harmless and noted in the feature's point 7.

An inner `timeout --signal=KILL`, as `launch` uses, would be wrong here. `timeout` runs as `agent` and is the program's parent, so the program's own `kill(-1)` would kill it, and `sudo` would report a death on every run. The drafter's choice is right; edit G puts the reason in the text.

- **Tester:** none, apart from the trap below, which the tester will not see: its own `make test` is red on purpose.
- **Coder:** `question`. Criteria 4 and 6 to 9 use the request's `os_user` `agent` and expect the program to run. In a stage, `make test` runs as `agent` (the coder's own `make check`), so `leftovers_due(..., os_user="agent", own_user="agent")` is false and those rows fail. In the factory's check, as `factory`, they pass. The coder cannot make its own `make check` green without changing the tests, so it asks. - **Coder, second trap:** the Interface bullet "A run with `resume_session` or a budget resume calls `_call` twice" is wrong. `ClaudeCodeRuntime.run` makes one call for a request with `resume_session` and a second one only after a budget stop (the same holds for opencode). A tester who writes a `resume_session` row expecting two programs gets a test the code cannot pass (edit B).
- **Reviewer:** none expected after edits A to F.
- **Documenter:** none. *The agent runs as a second user* (operator guide, line 96) and the paragraph *A `time_limit` under `sudo`* (line 196) exist, and so do `agents.md` *The agent runtime* and `watching.md` *Boundaries*.

## Running the real program as the tests' or the factory's user

No test or smoke test of this story does that.

- Every runtime test passes a stand-in as `leftovers`.
- Criterion 10 only reads the list.
- The existing wiring tests that run a call do so without an OS user (`_request(tmp_path, None)` from `tests/adapters/test_claude_runtime_os_user.py`).
- The ticks with `agent_user="agent"` run the fake runtime.

Even a test that slipped through would refuse rather than kill. A stand-in `sudo` does not switch users, so the real program would get `--user <os_user>` and run as the tests' user. If those are equal, `leftovers_due` is false. If they differ, the program refuses (S0001's second guard) and the run raises `cannot end the agent's processes: factory-leftovers: runs as ...`: a red test, never a kill.

## Points for the human, with recommended answers

1. The test user in the criteria (edit A): (a) a name no test runs as (`factory-test-other`); (b) the factory's own user read in the test, and `agent` only when it differs. Recommended: (a). It is simple and matches the smoke test.
2. A call that cannot be started (edit C): (a) the program follows only a call that returned; (b) it also follows a call whose start raised. Recommended: (a). Today's `_call` also skips the temporary folder's removal then, and nothing was started.
3. An operator's shell as `agent` (edit E): F0020-S0008's opencode single sign-on login and `claude setup-token` are run by the operator with `docker exec -u agent`. After this story the next agent call ends that shell. Recommended: say so in the operator guide, and run such logins while the instance is stopped.

## Verdict

Refused at intake as drafted (three questions); accepted with edits A to F, and the coder's stop is avoided by edit A. Edit G is optional.

Edit A (required, criteria 4, 6, 7, 8 and 9): every `os_user` `agent` becomes `os_user` `factory-test-other`, and every `--user agent` becomes `--user factory-test-other`. In criterion 4, `["-n", "-u", "agent", "--", <stand-in program>, "--user", "agent"]` becomes `["-n", "-u", "factory-test-other", "--", <stand-in program>, "--user", "factory-test-other"]`, and `The stand-in program records ["--user", "agent"]` becomes `The stand-in program records ["--user", "factory-test-other"]`. In the Interface's Tests paragraph, after "takes it from `pwd.getpwuid(os.getuid()).pw_name`." append:

```markdown
 A request whose `os_user` must differ from it uses `factory-test-other`, a user no test runs as: the tests run as `agent` in an agent's `make test` and as `factory` in the factory's checks, and a row with `agent` would start no program in the first.
```

Edit B (required, Interface, the bullet that starts "A run with `resume_session` or a budget resume"): replace with

```markdown
- A run stopped by its budget is resumed in a second `_call`, so the program runs twice, once after each call. A run with `resume_session` makes one call, and a second one only when its budget stops it.
```

Edit C (required, intake question 1):

- In the Interface, "In `_call`, after the call's process returned or raised:" becomes "In `_call`, after the call's process returned (a call that cannot be started raises `cannot start <program>: <error>` as today, and nothing follows it):".
- In the Interface, "When the call raised, or gives a refusal, the call's own `AgentRuntimeError` is raised as today, and an error of the program's start is not raised." becomes "When the call gives a refusal, the call's own `AgentRuntimeError` is raised as today, and the program's result is not read."
- In the Description, "It runs also after a call that raised." becomes "It runs also after a call that `sudo`, the write guard's wrapper or the login shell refused."
- In the Description, "When the call itself raised, or `sudo` refused it, that error stands." becomes "When `sudo`, the wrapper or the login shell refused the call, that error stands."

 An operator's shell opened as `agent` (`docker exec -it -u agent <container> ...`, for `claude setup-token` or an opencode login) is ended by the next agent call, so run it while the instance is stopped.

Edit G (optional, Interface, after the `leftovers_launch` bullet): insert
