**Code facts.**

- `run_sealed` is the only path for agent runs: the stage (`stage.py:112`, with `PatientRuns`, which resumes inside the one call) and the preflight's probe (`preflight.py:262`). So one reset per stage run keeps a resumed session, as decision 8 says.
- `InstanceSettings` has `agent_home`, `claude_login_file`, `api_login_file`, `opencode_folders` and `agent_user` as the story uses them. `Boundaries` is keyword-only with optional fields last.
- **`tests/test_wrapper_search.py::test_only_the_three_wrappers_import_the_process_module` pins the importers of `factory.adapters.process` to exactly `git_cli`, `make_commands`, `claude_runtime`, `opencode_runtime` and `entry.confine`.** `SudoAgentHome.reset` "starts, through `run_process`", so `factory.adapters.agent_home` imports `process` and that earlier test turns red. Feature decision 14 grants no leave. On the prototype: `FAILED tests/test_wrapper_search.py::test_only_the_three_wrappers_import_the_process_module`. There is no other route: every process goes through `process.py`, and `agent_launch` may not import it (`tests/test_agent_launch_search.py`). Edit 1 names the leave (feature edit 1).
- **The preflight's `lint` on `main` catches `(GitError, ProjectCommandError)` only** (`preflight.py:471`). A reset that raises `AgentRuntimeError` inside `SealedProjectCommands` leaves `Preflight.run` and `Tick.run`, and ends in `Scheduler._iterate`'s `except Exception` as `iteration failed: AgentRuntimeError: ...`. That happens on every iteration, with no stop and no health entry. It happens whenever the machine's items are skipped (same image) and a new `main` is probed. The docs criterion promises "`preflight_failed`" there, but only the agent-run probe gives that (`preflight.py:263`). Edit 2 raises the reset's fault as a `ProjectCommandError`, in line with S0001's decision 4.
- **The transcript does not stay "until the next run starts".** The stage's checks run right after every forward move (`tests`: `lint`; `doing`: `check`; `docs`: `check`, `secrets`, `documents`), each through `SealedProjectCommands`, which resets the home first. Only a run that asks, stalls or fails, or whose check result is reused, keeps its transcript until the next run. Edit 3 corrects the docs criterion; feature edit 3 corrects decision 10 and the operator's check 3.3.

**Clashes.** F0027 round 2's point 3 asked F0040 for a uv cache outside the fresh home. Decision 9 removes `~/.cache/uv` at every reset instead. A cache shared between runs must be writable by `agent`: uv refuses a cache it cannot write (`error: failed to open file /tmp/ro/CACHEDIR.TAG: Permission denied`, tried as `agent`). A shared cache is then a channel from one run to the next. See the feature's points. F0027-S0002's leftovers program and F0030's kill do not meet the reset: everything runs one after the other.

**Lease.** A reset normally takes about 0.1 s. A reset that hangs takes at most 90 s and stops the stage run, so it adds at most 1.5 minutes to the feature's 54.5 of 60 for `docs`.
