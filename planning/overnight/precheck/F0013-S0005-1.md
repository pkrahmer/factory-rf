### Edit 1: criterion 3, the bullet **Podman: the restart**

```markdown
   - **Podman: the restart.** `restart: unless-stopped` brings the container back after a crash and after `podman restart`, but not after the Podman machine (or the host) restarts. After a host restart, Docker Desktop starts the container by itself once Docker Desktop runs (its "start when you sign in" setting); the Podman machine must first be started (`podman machine start`, or Podman Desktop's start on login), and then Podman starts the container only through its restart service `podman-restart.service` inside the machine, enabled for the user that runs the containers (`podman machine ssh`, then `systemctl --user enable podman-restart.service`, and `loginctl enable-linger` so that it starts without a login). The service starts only the containers whose restart policy its `--filter` names: check it with `systemctl --user cat podman-restart.service`; if it names `restart-policy=always` only, the service does not start this container, and a Quadlet unit is the way. A Quadlet unit (a `.container` file under `~/.config/containers/systemd/` in the machine) is the alternative in any case, at the cost of leaving Compose for that instance. Until one of them is in place, after a machine restart the container stays `Exited (0)`: no tick runs, nothing is claimed or pushed, the health check does not run, so nothing shows unhealthy, and a lease the instance held expires; start it again with `podman compose -f image/compose.yml up -d`, and the factory goes on as after any restart (see *A restart during a stage*). The morning observation: `systemctl --user cat podman-restart.service` names a filter that takes `unless-stopped`; `podman machine stop`, `podman machine start`, then `podman ps -a` shows the container `Up` (not observed yet; plan step 2).
```
