## Facts checked

- **The Interface fits the architecture.**
  - `RecordLog` is an ABC in `factory.application.files` with docstring-only abstract methods, and `JsonLinesRecordLog` derives from it.
  - `RecordingProjectCommands` is an application service that derives from `ProjectCommands`. It reaches git only through the `Git` interface, so `tests/test_make_search.py` (no `make` literal outside the make class and the preflight) and the wrapper searches stay green.
  - `__init__` has five arguments beside `self`. The probe shows ruff's `PLR0913` counts without `self`, so it passes.
  - `tests/application/test_interfaces.py` reads `project_commands.py` for `Protocol` bases and abstract bodies only; a concrete class there breaks neither.
- **`GitCli.resolve` returns `None` for a missing ref.** A `GitError` comes only from a failing git (not a repository, a lost directory). The Interface's "a `GitError` gives `None`" covers both, and criterion 8 tests the second.
- **The wiring test and the built checkout.**
  - The leave (decision 36) is the one change `test_build_boundaries_picks_the_concrete_adapters_and_writes_nothing` needs. Its "writes nothing" still holds, since `JsonLinesRecordLog` creates its folder only on `append`.
  - `test_the_built_project_commands_run_in_the_checkout` runs `lint` in a checkout that is not a git repository. After the change it also resolves `HEAD` (`commit=None`) and appends a record under `tmp_path`, and it asserts only `last_line`, so it stays green.
  - The conftest boundaries keep `MakeProjectCommands`, so no stage or preflight test sees the recorder.
- **An Interface clause without a criterion.** "A `ProjectCommandError` or `ValueError` of `inner.run` propagates and records nothing": criterion 6 tests the `ProjectCommandError` only. v1's intake asks on the second branch of an "or".
- **The limits of `CommandRecord` on both sides** (`CLAUDE.md`: every limit tested on both sides).
  - Criterion 1 refuses a bad commit, `-1` and a status outside `CheckStatus`. It lacks the accepted `0`, the refused command name and the refused naive `started_at`.
  - `NonNegativeFloat` accepts `inf` (probe), and Pydantic then writes it as `null`. The line is unreadable afterwards and `read` skips it without a word.
  - `factory.domain.cost_records.Duration` (`ge=0`, `allow_inf_nan=False`) is the factory's own type for exactly this. Using it is the "shared helpers reused" rule.
- **Copies of fakes.**
  - The draft writes "a fake `ProjectCommands` written in the test". Two `RecordingCommands` fakes exist already. The one in `tests/application/test_preflight_run.py` takes an `answer(command, time_limit)` callable that can return the given result or raise, which is all this story needs.
  - Importing it follows the precedent of `tests/application/test_interfaces.py`, which imports `OPERATIONS` from `application.test_git_interface`.
  - Criterion 7's failing record log is needed again by S0016 (criterion 6). A shared `tests/record_support.py` holds one copy.
- **The dead-code record.** `RecordLog.read` and `JsonLinesRecordLog.read` have no caller in `src/factory` until S0016's `DiskRecorder.last`. Since H3, `make duplicates` runs after the coder, and vulture (`--min-confidence 60`) lists an unused method at 60 %. So the coder's entry carries one or two new dead-code findings. Saying so in the Assignment keeps the reviewer from sending the story back for code the Interface asks for.

The documenter, who runs every example it writes, cannot run it in v1's container, and the operator cannot run it in v1.1's. A `python3 -c` line with the `json` module runs in both.
