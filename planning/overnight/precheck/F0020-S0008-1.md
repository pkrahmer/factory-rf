# Pre-check F0020-S0008, round 1: the operator chooses the runtime per instance, and the image and the preflight carry opencode

I checked this story against v1.1's shipped roles and forms, and against factory-rf as it stood on 2026-10-18. The human sent a new fact during the pre-check (the coordinator relayed it):

- At the human's work, a company build of opencode logs in through the company's single sign-on, not with an API key.
- That build knows its own endpoint.

That fact makes three of this story's rules wrong for the work run. Those rules are E1 to E3 below, and the feature-level part is in `F0020-feature-1.md`.

## Checked against the built code and tests

- **E1: the key file (new fact 1).**
  - opencode can log in by a key or by a login it keeps in the home. S0001's login shell already hands over no key when the file is empty, and it reports `none`.
  - So the item has nothing to check about the key. The probe shows whether a run can log in, and its passed detail names the login in force (S0001).
  - Dropping the `size` parameter also removes a fault list that the work instance could never pass.
- **E2: the binary is the operator's (new fact 2).**
  - `FACTORY_OPENCODE` is already a setting, but only the image could set it, and the image does not.
  - The version item compares against `FACTORY_OPENCODE_VERSION`, which the image fixes at 1.19.3, so a company build of another version fails the item.
  - The models are the build's provider ids, which may not be `anthropic/...`.
  - The compose file therefore passes all three per compose call, with the image's values as defaults. A test pins the defaults to the Dockerfile's values, so the two files cannot drift.
  - How the company build gets into the container is the operator's business: a bind mount in a compose override file, or an image built on top. The docs criterion says so.
- **E3: the build's own folders (new fact 3).**
  - Decision 10 allows `<HOME>/.local/share/opencode`, `.local/state/opencode` and `.cache/opencode`.
  - opencode's own `auth login` keeps its state in `.local/share/opencode`, which is allowed, but the company build's single sign-on may keep it elsewhere.
  - The login may also refresh during a run, so the folder must be writable by the run.
  - A setting `FACTORY_OPENCODE_FOLDERS` (relative to the agent's home) adds folders to the rules; `factory-confine` makes them when they are missing (F0019).
  - The same setting fixes the open risk that opencode writes under `~/.config/opencode` (see S0004). The hand probe can then answer with a setting rather than a story.
- **Lost on recreation.** None of these folders is on a volume; only `/home/agent/.claude` is (`claude-home`). A login kept there is lost when the container is recreated.
  - Recommended: **the operator's step**, documented: log in once as the agent user after each recreation, or mount the folder with a compose override file.
  - A named volume in the shipped compose file would need a leave to change `tests/test_compose.py` again, and it assumes a folder nobody here has seen.
- **Wiring.**
  - `settings.agent_home / "settings.json"` is `/home/agent/.claude/settings.json`, which `image/entrypoint.sh` installs.
  - `which("sudo") or SUDO_EXECUTABLE` is today's pattern.
  - `build_boundaries(settings, "", hosting=FakeHostingService(), confine_executable=None)` makes no network call: `GitCli`, the logs and the record logs open no file when built.
- **Size.**
  - Before the edits: about 200 lines over settings, wiring, preflight, the Dockerfile and compose, with 14 criteria.
  - The edits add one setting and one runtime keyword, and remove the size check. That is still one pass, but the largest after S0004.

- **H2. The SSO login's persistence.** Recommended: **the operator's step, documented, no named volume now.**
  - The step is either a one-time login as the agent user after each container recreation, or a compose override that mounts the folder.
  - Revisit once the first run at work shows the folder.
- **H3. Proxy and CA settings at work.** The agent run's environment holds only `PATH`, `HOME`, `LANG`, `LC_ALL`, `TERM` and `TZ`.
