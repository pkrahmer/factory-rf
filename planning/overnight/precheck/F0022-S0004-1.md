## Code and document facts

- (1) The operator guide says "`.claude/*` is a protected path that no stage writes", as the story quotes.
- (2) The paragraph on the agent's home ends with "A `claude-home` volume made by an earlier image keeps its old owner and mode, so the protection holds on a new volume." That is the sentence the criterion inserts after.
- (3) The F0012-S0025 entry's `Open:` names "(a user `CLAUDE.md`, skills)". The F0022-S0002 entry's `Open:` bullet is the last line of `docs/decisions.md`. The acceptance report also named the F0010 entry of 2026-10-16 with a "2016" typo. No "2016" is in the log today, and that entry (line 297) does not name skills, so the story is right to leave it out.
- (4) "To change what an agent is told, edit its file under `claude/agents/`; there is no other copy." is at line 252, in the middle of *The seven agents*, not at its end: three more paragraphs follow.
- The entrypoint's fault, reproduced as root in a throwaway container:
  - a `/tmp/h` owned by `factory:factory-work` with mode `3775`, as the image's home;
  - as `agent`, `mkdir -m 0700 skills` with a file in a subfolder;
  - as `factory`, the entrypoint's loop under `set -e`.

  Output: `rm: cannot remove '/tmp/h/skills': Permission denied`, exit 1, and `commands` is never reached. So the text "`rm: cannot remove ...`" in the criterion is exact.
- **The volume's name is wrong in criterion 3.** The guide (line 344) and Compose (`name: factory-${FACTORY_INSTANCE}`) name the volume `factory-<instance>_claude-home`, for example `factory-self_claude-home`. The criterion's command uses `<instance>_claude-home`. An operator who puts `self` in it gets a new, empty volume named `self_claude-home`. The `rm` succeeds on that, and the instance still restarts.
