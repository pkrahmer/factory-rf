## Points for the human, with recommended answers

1. `main([])` in a test writes into `src/factory/contract/` unless the folder is replaced: (a) the row sets `CONTRACT_FOLDER` with `monkeypatch.setattr` on `factory.entry.contract` (a constant, not the code under test); (b) no test of the default folder. Recommended: (a).
2. The version rule (decision 15): (a) as drafted, the minor never rises; (b) the minor rises for an added optional field or an added value of a closed set, the major for a breaking change; a reader still ignores what it does not know. Recommended: (b): it costs one constant edit per such change and lets a validating reader pick the right schema; with (a) the minor carries no information.

Recommended edit (point 2 (b)), `feature.md`, decision 15, the third bullet, replace with:

```markdown
    - When it rises: the major on a field removed or renamed, a type narrowed, a value of a closed set removed, or a meaning changed; the minor on an optional field added or a value added to a closed set. A reader of one major ignores a property it does not know and treats a value it does not know as unknown, so it keeps working across minors; the generated schemas say `additionalProperties: false`, which states what this version of the factory writes. The reviewer checks the rule on every schema change; the test only catches a model change without regenerated schemas.
```

and the story's Description sentence "The version rises only for a change that can break a reader (a field removed or renamed, a type narrowed, a meaning changed), never for an added optional field." becomes "The major version rises for a change that can break a reader (a field removed or renamed, a type narrowed, a meaning changed), the minor for an added optional field or value."
