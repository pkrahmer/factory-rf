## Intake

`accepted`

- Interface: it names the four modules, the base `abc.ABC`, the decorator and the exact form of a method, the six implementations with their modules and unchanged constructors, and the test files.
- Criteria: each one can be tested by one test function. The rules have their failing sides: the docstring-only body (c6, an `ast` check), no `Protocol` base (c2), instantiation refused for the interface and for an incomplete subclass (c7, c8), no `__mro__` absence assertion (c13), the abstract class not counted (c14). c3 to c5 pin the abstract sets, and c9 to c12 pin the inheritance and the fixtures.
- Demo: both commands can run from the root with `uv run`, and each `Expect:` line gives exact output to compare against.
- Architecture: it matches `CLAUDE.md`'s Interfaces rule (ABC, docstring-only `@abstractmethod`, implementations inherit, `Protocol` only for foreign shapes). Adapters import application, which the layers allow. No DTO or operation changes.
- Scope: this is FEATURE.md's S0019 and decision 20, inside "Boundaries" scope (the four interfaces and their implementations), and touches nothing in "Out of scope".

A sharper intake could ask one thing. For `ProjectCommands` and `AgentRuntime`, the rule "no other public member and no state" has no criterion whose failing side would catch an extra non-abstract public member. c5 pins only `__abstractmethods__`; for `Git` and `HostingService` the existing protocol tests pin the public callables. This is unlikely to stop a low-effort intake.
