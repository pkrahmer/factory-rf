## The quick fix and the cause

The story calls `UV_COMPILE_BYTECODE=1` "the human's fix" in its Description, and "the answer" in its decision bullet. The bisection shows that it hides the cause and does not remove it: uv then compiles `.venv`'s bytecode at the sync, group-writable, so the test children find it and write none. But a child without `-B` still writes bytecode under the tests' umask `022` for any module that has none yet, and a `.venv` built by a plain `uv run` (without `make`'s export) has none. S0004 removes the cause in the test helpers. The decision bullet should say so, and name the `Makefile` line as the human's quick fix (required edits 1 and 2). I recommend building S0004 before this story, so that the bullet describes a fix that is on `main` (feature.md edit A of S0004's pre-check orders them so).

One smaller wording point: "`PYTHONDONTWRITEBYTECODE=1`, which `-I` or an emptied environment drops". An emptied environment drops the variable; `-I` keeps it in the environment and ignores it. Optional edit 3.

The two `grep -c` smoke blocks expect exactly `1`. The operator-guide criterion asks for the phrases in one place each, but a documenter who repeats `a bytecode folder` in the row and in the paragraph would make the block print `2` against correct text. A `grep -q` form expects only presence (optional edit 4).
