## Checked against the built code and tests

- **Claude Code's error result.** Claude Code prints `{"type":"result","is_error":true,"result":"API Error: ..."}` for an API error. Whether it retries an HTTP 428 first, and with which text, only a run at the human's work shows (decision 20).
  - **New fact:** the work instance runs on opencode. The Claude Code side matters only once a Claude Code instance can reach the gateway, and that needs the base URL of decision 21.
  - The Claude Code side is cheap (one branch in `_end_reason`), so I recommend keeping it.
- **The resume words.** `--resume <id>` with `-p <prompt>` is today's resume form, with the request's prompt in place of the finish message. The run files keep a fresh id, which is right, because the files are per call.
- **Stall text before S0007.** Between S0005 and S0007, a limit stalls with the sentence "lasted past the waiting ceiling" although nothing has waited yet. It is harmless, because S0007 follows. If the human stops after S0006, the sentence is wrong.
- **`limit_in_text` false positives.** A whole-number `428` matches any error result that names it. Elsewhere it is read only from the error result and standard error, so the agent's own text cannot trip it.
- **`named_wait` false positives.**
  - `in <n>` with no unit (seconds) also matches phrases such as "in 2026", which gives 2026 seconds.
  - A gateway text like "per 10 minutes" is not matched, because it says `per`.
  - S0007 caps every wait at the ceiling, so a misread wait costs time and nothing else.
- **Size.** About 150 lines over eight modules and 17 criteria, within one pass.
