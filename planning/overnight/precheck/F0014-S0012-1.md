## Facts checked

- **The code.** `book_merge` calls `_booked(document, "accepted", <text>, at)` on both branches. The `before_approval` text is `_MERGED_BEFORE_APPROVAL_PREFIX + cost_line(bill)`, the other `done_entry_text(bill)`. `AcceptanceMerged` passes `before_approval=is_before_approval(...)` and `at=boundaries.clock.now()`. The Interface states this correctly.
- **What pins it today.** S0007's criterion 6 is `tests/domain/test_journal_stamps.py::test_booking_records_the_done_entry_with_the_time_and_the_done_stage`. Its `booking` rows are `merge` (`book_merge(_report(), bill([]), at=at)`) and `refusal`, crossed with the `at` rows `with-at` and `without-at`. No row has `before_approval=True`. `test_acceptance_before_approval.py` calls the branch without `at`. The handler tests of the branch check the stage, the outcome and the text, never `at`. This confirms the acceptance's survivor.
- **Where the rule's sides belong.** The rule is S0007's criterion 6 ("given `at`, the done entry carries it and `stage` = `done`; without, as today"). Its sides are rows of the one test above. The drafted criterion 1 makes a new parametrized test over `before_approval` true and false. Its `false` rows repeat that test's `merge` rows, and the rule's sides would sit in two tests. `CLAUDE.md` says "The sides of one rule are rows of one parametrized test, not separate test functions", and the reviewer counts such a split. The test that fits is a third `booking` row, `book_merge(_report(), bill([]), before_approval=True, at=at)`, in S0007's test. That is a change to a test S0007's tester wrote, so it needs a FEATURE decision giving the leave (edit 1).
- **The row against the built code.** `_report()` is an `AcceptanceState` at `approval` with three records, so the done entry is number 4 on both branches, which is what the body asserts. `book_merge` does not read the stage for `before_approval`, so the row is valid test data. The `at` → `None` mutant on that branch gives `(None, None, None)` in the `with-at` row, so it is killed. The row's function is a `Callable[[datetime | None], WorkItemDocument]`, like `_merge`, and passes `mypy --strict`.
- **Criterion 1's text check.** "Its text starts with the row's prefix" is pinned already on both branches: `test_a_merge_before_approval_books_like_a_merge_with_an_entry_that_says_so` and the handler tests compare the whole text. Leaving it out loses nothing.
- **Criterion 3 (through the handler).** `test_acceptance_merged_before_approval.py` gives `publish("acceptance")`, `merge(...)` and `_booked(boundaries, checkout)` (the state and the last text from `done/` on `origin/main`). A new function there can assert `state.journal[-1].at == boundaries.clock.now()` and `.stage == "done"`. The `clock` fixture is a `ManualClock` that nothing advances, and `at` survives the front matter round trip, as S0007's `test_acceptance_merged.py` change shows. A new function in an existing module changes no earlier test (decision 27's rule). The application call passes `at` for both branches already, so this criterion kills the same domain mutant again, through the handler. It is cheap and matches the Assignment's "through the merge handler".
- **Docs criterion.** `none` holds. The project guide already says "The acceptance's `done` entry carries `done`, since its booking sets the stage first", and that every entry the factory appends carries `at` and `stage`. The reason given ("the decision log's journal entry already says every new record carries the stamp") is close enough. The project guide is the better source (edit 2).
- **Write paths.** `tests/*` only (the tester's lane). No human change.
- **Size.** One row, one new test function. Far inside every budget and the lease.
