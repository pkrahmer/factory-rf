## Facts checked

- **The modes do what decision 28 says.** `3775` is setgid, sticky and `rwxrwxr-x`: the agent (group `factory-work`) can create files in the home, new files keep the group, and the sticky bit lets it remove or rename only its own. `agents/` at `0755` and the files and `settings.json` at `0644`, owned by `factory`, are read-only to the agent. A `claude` that refreshes its own `.credentials.json` by renaming a file of its own over it still can.
- **The entrypoint can do it.** It runs as `factory`, which owns the home, so `rm -rf "$home/agents"` and the `cp` work as today; the files it makes are `664`/`775` under `umask 002`, then the `chmod`s set `644`/`755`. `claude/agents/` has no subfolder, so "every file in it `0644`" is safe.
- **New volumes are filled from the image.** Docker copies the mount point's content, owner and mode into an empty named volume; S0022 makes every v1.1 volume new (`factory-<instance>_claude-home`). An older volume keeps its owner `agent` and mode `2775`, and on it the protection does not hold (the agent could rename `agents/` away).
- **One Interface clause has no criterion**: the entrypoint sets the modes "before the line `installed agents and settings into <home>`". v1's intake step 3 lists an ordering among the behaviours a criterion must test, and none does; it cannot be observed from outside either (the modes are the same after the run whatever the order).
- **What stays writable** (decision 28 keeps it so): the agent can still add files of its own to `~/.claude` that `claude` reads on later runs (a user `CLAUDE.md`, `skills/`, `commands/`), and `/home/agent/.claude.json` (outside the volume, in the agent's own home) holds `claude`'s per-project settings and user-scope MCP servers. The plan's item 1.10 asks for the agent files and `settings.json` only, so this is not a gap of the story; the docs should not claim more.
- **The leave** (decision 42) moves the one row; the `/work` row stays. Criterion 1 reads the Dockerfile the way `_path_settings` does (the last `chown` and `chmod` per path).
- **Demo on today's code**: the Dockerfile `grep` prints four lines (the `mkdir`, `chown agent:factory-work`, `chmod 2775 /work /home/agent/.claude`, and the `ENV FACTORY_CLAUDE_HOME`); the entrypoint `grep` prints only `chmod 2750 "$state/runs"`. After the story the expected lines are there; the extra `mkdir` and `ENV` lines do not contradict the `Expect:`.
