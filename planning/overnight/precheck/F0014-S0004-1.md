## Facts checked

- **Users and groups.** `factory` is uid 1000, `agent` is uid 1001, and the primary group of both is `factory-work` (gid 1002). The group `factory` (gid 1000) has no member. So on a Linux Docker host, `1001:1002` with mode `0440` works as decision 12 says: the agent reads the file as its owner, and the factory reads it through its primary group. The docs criterion's wording is right.
- **`/home/agent` can be traversed by `factory`.** The entrypoint runs as `factory` and installs into `/home/agent/.claude`, and this worked at the first start. So the factory can reach `/home/agent/.claude-token`.
- **`create_host_path: false` on a file bind mount** is the same long-syntax mount as the hosting token's, which ran at the first start under Docker Desktop and under Podman with the docker-compose v2 provider. No new mechanism: with the source missing, the engine refuses with `bind source path does not exist`. Podman-compose is out of scope (F0013), and it would also fail on a missing source.
