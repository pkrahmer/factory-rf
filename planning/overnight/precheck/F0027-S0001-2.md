## Points for the human

1. **Two `ProcessEntry` models and two readers of `/proc` (clash with F0030-S0001).**
   - F0030-S0001 adds `factory.domain.sessions.ProcessEntry(pid, session, ended)`, read from `/proc/<pid>/stat`, to `factory.adapters.process`.
   - This story adds `factory.domain.leftovers.ProcessEntry(pid, uid, state)`, read from `/proc/<pid>/status`, to `factory.adapters.own_processes`.

   That is two models of one name and two table readers. F0039 ("the code says what it does once") and the reviewer's rule on a second copy of a helper (`CLAUDE.md`) count that as a finding.
   - (a) Whichever is built second extends the first one's entry and reader by its field, and the second story's Interface is edited before it starts.
   - (b) Keep both. They differ in what they read, and the names live in different modules.

   Recommended: (a), F0030 first, since it is ready and touches only `process.py`. This story's entry then gains `uid`, read from the `Uid:` line, or from `os.stat("/proc/<pid>").st_uid`.
2. **F0040 (project commands as the agent's user).** Once the factory's checks also run as `agent`, this program must also follow every project command run as `agent`, or a process a check leaves runs on into the next agent run. Decision 8's sentence "`factory` becomes `agent` only for agent runs, their temporary folder's removal and this program" becomes false. Recommended: F0040 reuses `leftovers_launch` (S0002) after each project command, and says so in its own decisions.
