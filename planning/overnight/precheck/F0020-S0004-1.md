  - `write_opencode` cannot reuse the claude stand-in's `SCRIPT` as it is. That script records only files named by its arguments, so the configuration named in `OPENCODE_CONFIG` would be missed.

- **The os.environ search (E3).** Changing `tests/test_agent_run_request_search.py` would need a leave, so a new module is cleaner. It extends S0002's E2 test, which names `agent_launch`, by the new module.
- **detect-secrets.** Criterion 14's key rows need S0001's E3 rule: the key's value goes in a name without `key`, and the environment is written by constant.

## What the story assumes beyond the probe

The probe saw:
- `run --format json` with standard input closed;
- the events `step_start`, `text`, `tool_use` with `state.status` and its error, and `step_finish` with `tokens` and `cost`;
- `sessionID` and a timestamp on every event;
- `--agent`, `--session`, `--auto`, `--variant`;
- a `bash` permission per pattern in `opencode.json`;
- `"edit": "deny"` removing the edit tools;
- the snapshot folder.

The story assumes, and only the hand probe or the real run can show:
- that `OPENCODE_CONFIG` is read;
- the `agent` map with `mode`, `prompt`, `tools` and `permission` per agent;
- the keys `snapshot`, `share` and `autoupdate`;
- the long option `--model` (the probe used `-m`);
- the field names `part.tool`, `part.state.input`, `part.state.time.start` and `.end`, `part.tokens.cache.read` and `.write`, and `part.cost`;
- the `error` event's shape `error.data.statusCode` and `error.data.message`;
- that `"*": "allow"` followed by denies gives the denies precedence;
- that opencode writes nowhere in the home but the three folders. It may install provider packages under `~/.cache/opencode`, which is allowed. A write under `~/.config/opencode` would be refused, and every run would die (see S0008's E3).

Decision 20 names most of these. The `error` event's shape and the order of the permission rules should be named there too (feature edit F6).
