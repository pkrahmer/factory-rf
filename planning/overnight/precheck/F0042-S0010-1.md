## Intake outcome (as v1.1's intake would end)

`question`:

1. Criterion 5 asks that the opencode runtime's `confine_executable` be `None`. `OpencodeRuntime` has no such property on `main`, and S0008 adds none, so the test could only read a private attribute. Should the row prove it through S0008's `ValueError` instead (the build succeeds with `confine_executable="factory-confine"` given) and read only `containers` and `leftovers` for opencode?
2. The Interface says that `which`, `confine_executable` and `end_leftovers` are read for `inline` only. No criterion builds a container instance with them set. Should criterion 5 build with a recording `which`, `confine_executable="factory-confine"` and `end_leftovers=True`, and see `which` not called?
3. The Interface says that every variable is stripped and that a blank value counts as unset, and that `FACTORY_PODMAN` and `FACTORY_ZFS` "unset or blank" give their defaults. Only the stripping of `FACTORY_STAGE_ENVIRONMENT` and the unset side of the defaults have rows. Should criteria 1 and 2 gain the blank and the padded rows?
4. The Interface's Tests line says "nothing is run", while criterion 5 runs `snapshots.reset()` against a stand-in `zfs`. Which holds?
5. (smaller) Under `inline`, is a relative `FACTORY_WORKSPACE` accepted? The model accepts "any combination", but the reading only says that a missing one is no fault. In criterion 9, the operator guide's table has three columns, not five, and the guide's `README.md` line for `stage-environment.md` is not named.

## Points for the human

1. **The login files of a container instance's runtime have no criterion.** The Interface says the runtime is built "with the login files, models and limits as today". S0008's tests pin that a runtime given login files mounts them. Nothing pins that the wiring gives them. No public property shows them, so only a run shows them.
   - A: leave it. A slip shows on F0043's story 4, the first stage on the VM, as a run without a login. Cheap now, dear then.
   - B: edit 6. One more row in criterion 5: a run against the podman stand-in, which prints a completed reply and records its words, and the recorded words hold `--volume <login>:<login>:ro`. I could not prototype this row, because S0008 is not built.
   - Recommended: **B**. The wiring is the only place where the login reaches the container runtime.
2. **The VM's checkout and state paths have no setting.** `InstanceSettings.checkout` and `state_directory` are fixed at `/work/checkout` and `/state`, and no variable reads them. The plan puts the factory's clone at `/srv/factory/<instance>/repo` on the host. A host checkout at `/work/checkout` next to a workspace of `/work` would also make the dataset's `checkout/` the factory's own work tree, which every rollback resets.
   - A: leave it to F0043. Its story 2 (the setup) adds `FACTORY_CHECKOUT` and `FACTORY_STATE`, with a fault when the checkout lies inside `FACTORY_WORKSPACE`.
   - B: widen S0010 with those two settings and the fault now.
   - Recommended: **A**. S0010 is full, and the VM's layout is F0043's to decide. Note it in F0043's draft so that its pre-check finds it.
