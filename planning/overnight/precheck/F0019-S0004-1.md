## The order on the command line (the brief's first check)

S0004 builds, with an `os_user`:

`sudo -n -u agent -- timeout --signal=KILL <limit>s env -i <assignments> factory-confine --rules <file> -- /bin/sh -c <login script> factory-login <login file> claude ...`

**This order is right, and it is the only right place:**

- **After `sudo`.** `landlock_restrict_self` needs `no_new_privs`, which survives `execve` and makes the kernel ignore set-uid bits. A confined process that ran `sudo` would not become root. sudo 1.9.13 refuses with `sudo: The "no new privileges" flag is set, which prevents sudo from running as root.`, so a wrapper before `sudo` would end every run at once.
- **After `env -i`.** `env -i` drops every variable it is not given, so a wrapper before it would lose its `TMPDIR`. After it, the wrapper sets `TMPDIR` itself, and `CLAUDE_CONFIG_DIR` comes in among the assignments.
- **Before the login shell and `claude`**, so both inherit the domain. The login shell only reads the login file, and reads stay open.
- **`timeout` stays outside the domain.** It forks one child and signals it. That child `exec`s `env`, `env` `exec`s `factory-confine`, which `exec`s the shell, which `exec`s `claude`, so the kill still lands on the runtime (decision 5).
- **Without an `os_user`**, the wrapper is the program `run_process` starts, in its own session, so the factory's kill of the group reaches it.
- **The removal runs unconfined.** It is `sudo -n -u agent -- /bin/sh -c …`, started by the factory itself, and is allowed by the sudoers rule.
- **Nothing inside a run needs `sudo`.** An agent that tries it gets the refusal above, which is intended.

## Checked against the built code and tests

- **Two earlier tests turn red (E1).**
  - With `confine_executable=CONFINE_COMMAND` always set by `build_boundaries`, both tests above start `factory-confine` by name.
  - Their requests have no `PATH`, so `Popen` searches the default path (`/bin:/usr/bin`) and raises `FileNotFoundError`. The runtime turns that into `AgentRuntimeError: cannot start factory-confine`.
  - Even with a `PATH`, their stand-in records `calls.jsonl` in `tmp_path/bin`, which no rule allows, so it would die.
  - The story says "No earlier test module changes", and decision 13 says earlier tests "build it without the argument". Both are wrong for these two.
  - So the coder's `make check` is red on tests it may not change, and it ends with `question`.
  - E1 gives `build_boundaries` a keyword that defaults to the wrapper, so production stays confined (`run.py` and `boundaries_from_environment` pass nothing). The leave covers one argument in each of the two tests. `build_boundaries` then has five parameters, within `max-args`.

  - Files: `README.md`, then the device files.
- **The real wrapper in these tests.**
  - The stand-in `claude` is a Python script whose shebang is `sys.executable`, under the checkout in a tool path. It reads its arguments' files (reads stay open) and writes `calls.jsonl` beside itself (allowed).
