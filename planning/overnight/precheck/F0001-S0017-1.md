## Facts checked

Each behaviour is built as the Interface says, so the tests pass at once:

- `MakeProjectCommands.run` checks `time_limit`, then `_COMMAND_NAME.fullmatch(command)` with `^[a-z][a-z0-9-]*$`, and raises `ProjectCommandError` before `run_process`. `fullmatch` refuses `"check\n"` (`$` matches before the newline, but the match must span the whole string). The existing `test_invalid_command_name_is_refused_before_starting` is parametrized with three other names. The new case must be a new test function: adding it to that parametrization changes a test the tester did not write, which is "Not without asking".
- `GitCli.move` runs `check_repository_path(source)` and `check_repository_path(destination)` before `mkdir` and before git (`git_cli.py` lines 322 to 325).
- `GitCli.status()`: a porcelain v2 `u` entry gives `ChangedPath(path=entry.split(" ", 10)[10], change="modified")`. On the host, a real conflicting `git merge` left in progress gave `changes=[ChangedPath(path='f.txt', change='modified')]`: once, `modified`.
- `FakeHostingService.delete_comment(number, comment_id)` filters only the comments of pull request `number`, and comment ids count across all pull requests. Another pull request's id therefore raises `HostingServiceError` and changes nothing.

Further facts:

- **`run_git` cannot make the unmerged state.** The Interface says "The unmerged state is made with plain `git merge` through `run_git`". But `run_git` asserts `exit_status == 0`, and a conflicting merge exits 1 (seen on the host), so that call fails the test with `AssertionError`. The tester has to call `run_process` directly with an isolated environment, as `test_committed_at_is_the_committer_date_in_utc` does in the same module. Criterion 3 itself ("run with plain git") allows that. Only the Tests note is wrong.
- **The Demo prints no summary line.** `pyproject.toml` has `addopts = "-q --strict-markers"`, and the Demo adds a second `-q`. With pytest 9.1.1, `-q` twice prints only the progress dots and `[100%]`, with no `N passed in …` line. I checked this on a two-test module: with `-q` it printed `..   [100%]` and nothing else; without it, the line `2 passed in 0.00s`. The `Expect:` line ("the summary line reports only passed tests") names a line the command does not print. The coverage threshold does not interfere, because `--cov` is only in the Makefile.
- The four test modules exist. None of them has a skip or xfail mark, so the summary would be clean.
- **The docs criterion contradicts itself.** It begins "docs: none." and then asks the documenter to add a sentence. `stage-docs` step 2 says "If the criterion says `none`, write nothing new." The other three behaviours are documented: `docs/project-guide.md` line 208 (full match), line 176 (`move`, both arguments), line 139 (unmerged is `"modified"`). The fake's table (line 63) is where the new sentence goes.
- Write paths: only `tests/*` (tester) and `docs/project-guide.md` (documenter). No code, dependency or `factory/` change.
