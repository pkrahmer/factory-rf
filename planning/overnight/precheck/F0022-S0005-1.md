I checked the story against v1.1's intake (`claude/agents/intake.md`, `factory/story-form.md`), the tester's and reviewer's texts, `CLAUDE.md` (*Tests*, the standing leave to move a shared helper; *Checks*, `mypy --strict` over `tests`) and `pyproject.toml` (`[tool.mypy] strict = true`, ruff's rules, pytest's options). ## Code facts

What the story counts is right:

- **`ENVIRONMENT`:** the value `{"PATH": "/opt/factory/bin:/usr/bin", "HOME": "/home/agent", "LANG": "C.UTF-8"}` is assigned in exactly the four probe modules (`grep` count `4`).
- **`COMPLETED`:** with `entry="probe"`, it is in `test_agent_run_probe.py` and `test_agent_run_probe_project_agent.py`. Three wiring modules also hold a `COMPLETED = AgentRunResult(`, with `entry="checked."`, and contain `entry="probe"` elsewhere in the file. So criterion 2 means the assignment's own arguments.
- **The `settings` fixture:** the same body in the three modules named. The fixtures of `_api_login` (login files) and `_opencode` (installs an agent, opencode) are other fixtures.
- **`PROJECT_CODER = AGENT_FILE.replace(`:** in two modules (`grep` count `2`). `AGENT_FILE` already lives in `tests/git_support.py`, so `PROJECT_CODER` can go there without a new import cycle.
- **`return Layout(tmp_path)`:** in three modules (`grep` count `3`), each fixture named `layout`. `test_agent_home_ownership.py` and `test_entrypoint_skills.py` import `Layout` from `test_entrypoint`.

Two facts the story does not know:

1. **`tests/conftest.py` already imports a `Layout`: the confinement's** (`from confine_support import Layout, build_layout`, line 13), the return type of its own `layout` fixture. The new `image_layout` fixture needs `test_entrypoint.Layout` under another name. The only ways to keep the literal `return Layout(tmp_path)` in `conftest.py` are these:
   - rename the confinement's import, which is the "stays as it is" fixture;
   - an import inside the fixture's body.

   Otherwise the line becomes, for example, `return ImageLayout(tmp_path)`. Then criterion 2 and smoke block 2 (`grep -rlF 'return Layout(tmp_path)' tests | wc -l`, expected `1`) print `0` on a correct move.
2. **`test_agent_run_probe_api_login.py` imports `ENVIRONMENT` from `application.test_agent_run_probe_login`** (line 8). Once that module imports `ENVIRONMENT` from `probe_support` instead of assigning it, `mypy --strict` (`no_implicit_reexport`) refuses the import. I prototyped exactly that change on the copy and ran the checkout's mypy over it:

   ```
   tests\application\test_agent_run_probe_api_login.py:8: error: Module "application.test_agent_run_probe_login" does not explicitly export attribute "ENVIRONMENT"  [attr-defined]
   ```

   The other errors of that Windows run were the platform's `os.geteuid` errors, which are not this story's. So `make check` turns red unless `_api_login` changes too. It is not among the story's eight modules, and criterion 1 does not cover it.

Also seen:

- `tests/application/test_nested_repositories.py` holds a plain function `_probe_settings(tmp_path, agent_home)` with the same body. It is a function, not a fixture, and it does not clash with the name `probe_settings`. The next reviewer may still call it the "fifth copy" the Description warns of.
- Smoke block 3 counts `' passed'` in pytest's last line. `1 failed, 41 passed in ...` also contains it, so a red run prints `1`. The block also runs only five of the eight changed modules: `test_agent_run_probe_opencode.py`, `test_entrypoint.py` and `test_agent_home_ownership.py` are missing. None of the modules has a skip mark.
