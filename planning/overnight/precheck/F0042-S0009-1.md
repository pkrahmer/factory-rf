## Intake outcome (as v1.1's intake would end)

`question`:

1. Criterion 3 states `exit_status` 1 for a `sync` that exits 1. GNU make exits 2 when a recipe fails (`tests/adapters/test_make_commands.py::test_failing_recipe_fails_with_the_status_make_sets` pins 2), and the check container's exit status is make's. Should the row say `exit_status` 2?
2. The Interface states `output_tail` (the last 30 lines), and the Description says a file a check makes stays in its container. Neither has a criterion. Should criterion 1 pin both?
3. The Interface says `GitError` from `changed_paths` and `ValueError` from `copy_changed` propagate as they are. Neither side has a criterion. Should criterion 6 gain two rows?
4. (smaller) Criterion 5 tests `time_limit` 0, but the rule is "0 or less". Criterion 1 writes `TargetTime` positionally, which pydantic refuses. Criterion 2's deletion and change rows only bite when the base holds `src/old.py` and `src/kept.py`, which the story does not say.
