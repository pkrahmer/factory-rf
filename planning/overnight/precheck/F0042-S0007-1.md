Two findings:

- **Run 1b: a fresh repository refuses the fetch when the default branch name is one the host has.** `git init` leaves `HEAD` on an unborn branch (`master` here, `main` wherever `init.defaultBranch=main` is set), and git refuses to fetch into the checked-out branch, unborn or not; the script cannot detach an unborn `HEAD`. Run 1 passed only because the host has no `master`. The variant without the detach step and with `git fetch -q --prune --update-head-ok` passed all cases under `init.defaultBranch=main`: a fresh repository, a second prepare for the work item's branch, a third for the very branch that is checked out after a new host commit on it (a dirty `story.md` in the dataset was put right: `HEAD` the new commit, the work tree clean), a fourth back to `main`, and a host branch forced back to an earlier commit (taken by the `+`). The checkout and the reset after the fetch put the work tree right, so `HEAD` need never be detached (edit 1, point 1).
- **Runs 4 and 5: the last line of a failed `make sync` is make's own message.** The output ends with `make: *** [Makefile:3: sync] Error 1`, so the Interface's step 3 ("the last non-blank line of the output") gives that line as the `detail`, while criterion 5 expects `boom` and S0011's criterion 6 expects `container command sync failed: boom`. The rule that skips make messages is the adapter's private `_last_line`, which the application layer cannot import (edit 2, point 4). Run 5 shows the `exit status <n>` branch is unreachable through make (make always prints its message); it is reached only through a result whose output is empty or make messages alone, which a stand-in `ContainerRuns` gives (edit 2).

Also seen: `--prune` removed `gone` (criterion 4 has no clause for it: edit 3); the copy replaces `.claude` (a stale file is gone); the first prepare's commit stays an object; a bad commit ends the script at git's message before `make sync` runs (the marker count stayed at the earlier run's one).
