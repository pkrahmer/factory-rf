## Checked against the built code and tests

- **The re-exports (E1, required).**
  - Every earlier test that imports `LOGIN_SCRIPT`, `LOGIN_VARIABLE` or `SHELL_EXECUTABLE` from `factory.adapters.claude_runtime` needs the name exported there, or `mypy --strict` reports `attr-defined` (no implicit re-export).
  - The Interface's `as` form is `PLC0414` under the project's ruff rules.
  - The project's own precedent is `__all__`: `factory.domain.settings` re-exports `DEFAULT_GIT_IDENTITY` that way, and `factory.entry.wiring` re-exports `judge` and `read_guard_settings`. mypy treats a name in `__all__` as exported. ruff neither flags it as unused nor calls the alias useless.
  - Names defined in the module but missing from `__all__` stay importable under mypy (`wiring` imports `CREDENTIAL_FILE_VARIABLE` from `settings` today).
  - So `__all__` needs to list only what is re-exported, together with the module's public classes and functions.
- **`SHELL_EXECUTABLE` set by a test.** Today the only tests that set `claude_runtime.SHELL_EXECUTABLE` run `confined_runtime` without a login file, so they reach only the removal. After the move, `login_argv` uses `agent_launch`'s constant, and those tests still pass. That is right, and the Interface says so.
- **The script.** Under `env -i` the order is sudo, timeout, `env -i`, confine, login shell, `claude`, so the login shell runs confined. It reads its files before the `exec` and writes nothing, so Landlock refuses nothing.
- **Criterion 12.** The stand-in's `Step(writes={<api file>: ""})` is applied before it prints, so the resume reads an empty file. This is doable with today's support module.
- **The fixture (E2, required).** If the tester imports `recorder` as the Interface says, `make lint` (the tests stage's check) is red: `F811`. The standing leave covers moving `Recorder` and `recorder` to `tests/conftest.py`, from both modules that hold a copy. Without E2 the tester may still find this, but the Interface tells it to import.
- **Test values (E3, recommended).** `make secrets` runs in the coder's `make check`, not in the tester's `make lint`. A test constant like `API_KEY = "..."` or a dict literal `{"ANTHROPIC_API_KEY": "..."}` would therefore reach the coder red. The coder may not edit tests, so it becomes a question and a round. The existing login tests avoid this by using `LOGIN = "stand-in-login"` and `{LOGIN_VARIABLE: LOGIN}`.
- **Write paths.**
  - Coder: `src/*`, `image/Dockerfile`, `image/compose.yml`.
  - Tester: `tests/*`.
  - Documenter: `docs/*`.
  - Human: the empty host file (change 1).
- **Size.** About 150 lines of source over seven modules and nine test modules. That is within 40 minutes, but the tester's list is long, with 21 criteria. F0019-S0004, of the same weight, needed 25 runs and $10.47.
