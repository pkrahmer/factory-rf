## Intake outcome (as v1.1's intake would end)

Decision `question` (likely). Entry:

```
1. Interface, first bullet: the RUN stands "right after the RUN that adds the users (useradd ... agent) and before WORKDIR /opt/factory". Criterion 2 tests only that it comes after the useradd RUN and before USER factory, so "right after" and "before WORKDIR" have no criterion. Should criterion 2 pin that it is the instruction right after the useradd RUN, or should the Interface say only "after the users exist and before USER factory"? I would pin it in criterion 2.
```

The intake's lesson is "every clause of an Interface rule has its own criterion, ... an ordering". Every other clause has its criterion:

- the owners and modes of both folders, and the no-write bits (criterion 1);
- exactly one `mkdir -p` `RUN` (criterion 2);
- `RUNTIME_FOLDERS` unchanged (criterion 3).

The bullet "each `chown` names one owner without `-R`" is pinned indirectly: with `-R`, `_path_settings` would read `-R` as the owner, and criterion 1 fails. With edit 1 the entry becomes `accepted`. The architecture line would say that the image is the coder's (`image/*`), and the scope line that the story is within F0029's Scope.
