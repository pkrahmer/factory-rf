### What python-frontmatter 1.3.0 does (checked in the project's `.venv`)

- **How a handler is given.**
  - `frontmatter.loads(text, encoding="utf-8", handler=None, **defaults) -> Post` and `frontmatter.parse(text, encoding="utf-8", handler=None, **defaults) -> tuple[dict[str, object], str]`. `load(fd, encoding, handler, **defaults)` and `dump(post, fd, encoding, handler, **kwargs)` do the same for files.
  - `frontmatter.dumps(post, handler=None, **kwargs) -> str` calls `handler.format(post, **kwargs)`. When no handler is given, it uses `post.handler`, or else `YAMLHandler()`.
  - A custom handler subclasses `frontmatter.default_handlers.BaseHandler`, or `YAMLHandler` to keep the YAML boundary, and overrides `load(fm)` and `export(metadata)`. `detect(text)`, `split(text)` and `format(post)` are inherited.
- **Preparing the text.** `parse` first turns `\r\n` into `\n` and removes the whitespace around the whole text (`u(text).strip()`). Blank lines and spaces before the opening line therefore do not count.
- **The boundary.** `YAMLHandler.FM_BOUNDARY = re.compile(r"^-{3,}\s*$", re.MULTILINE)`, with `START_DELIMITER = END_DELIMITER = "---"`.
  - A boundary line is three or more `-` followed only by whitespace. `---`, `----`, `-----`, `--- ` and `---\t` are boundary lines. `--- x` and `- - -` are not.
  - A closing ` ---` with a leading space is not a boundary line. An opening one is, because the strip removes the space.
- **`detect(text)`** is `FM_BOUNDARY.match(text)`: the text starts with a boundary line.
- **`split(text)`** is `_, fm, content = FM_BOUNDARY.split(text, 2)`. The front matter is the text between the first two boundary lines, and the content is everything after the second. Fewer than two boundary lines raise `ValueError`.
- **Four traps** for a reader that calls `parse` or `loads` with a handler (probed):
  1. When a handler is given, neither calls `detect`. The text `# T\n\n---\nmiddle: 1\n---\n\nend\n` gives the metadata `{'middle': 1}` and the content `end`, and drops the title.
  2. When the front matter is never closed, they return `{}` and the whole text. The caller cannot tell this from an empty front matter.
  3. `parse` keeps the loaded value only `if isinstance(fm_data, dict)`, so a list as front matter silently becomes `{}`.
  4. `loads` builds `Post(content, handler, **metadata)`, so a front matter key `content` or `handler` raises `TypeError`. `parse` does not.
- **The layout `dumps` writes.** `DEFAULT_POST_TEMPLATE` is `"{start}\n{metadata}\n{end}\n\n{content}\n"`, with the whitespace around the result removed. That gives `---`, the exported YAML, `---`, an empty line and the content, with no final newline. For an empty content the text ends with `---`. `export` must return the YAML without a final newline, or an empty line appears before the closing `---`.
- **Typing.**
  - The package ships `py.typed`, and mypy reports nothing about PyYAML inside it.
  - `YAMLHandler.load` is typed `-> Any`, so an override typed `-> dict[str, object]` is accepted. That return type also passes `tests/test_no_untyped_dicts.py`, where `dict[str, Any]` would not.
  - `frontmatter.Post(body, **values)` with `values: dict[str, object]` is a mypy `arg-type` error, because `**` could fill the `handler` parameter. `frontmatter.Post(body, None, **values)` passes.
  - Ruff's `ARG002` reports the unused `**kwargs` of the overrides unless they carry `typing.override`.

2. **S0003, Interface, the second rule** (replaces "The adapter splits the text by this rule itself … (decision 4 of `FEATURE.md`)."):

   "- python-frontmatter splits the file and ruamel.yaml reads and writes its YAML (R13). `RuamelYamlHandler` subclasses `frontmatter.default_handlers.YAMLHandler`.
