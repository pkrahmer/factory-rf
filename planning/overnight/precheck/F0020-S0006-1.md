## Checked against the built code and tests

- **Stopping at the budget.** The callback adds `Decimal(str(cost))` on each `step_finish` and compares with `>` against `budget_usd`, so 0.4 + 0.4 + 0.2 = 1.0 is not above 1.
  - Criterion 1's sum is exact in `Decimal` (`str(0.4)` is `0.4`).
- **Stopping at a limit.** An `error` event with `statusCode` 428, or with the message in `limit_in_text`, stops the run. A `text` or `tool_use` event never does. Criterion 11 pins the second rule.
- **What only the real run shows.**
  - Whether opencode 1.19.3 prints an `error` event on HTTP 428 at all, or retries quietly, or stalls with no line. The human's brief says it stalls and waits for "continue".
  - If it prints nothing, the run ends `time_limit` after the coder's 40 minutes and stalls, with one attempt counted. The feature's decision 20 names this as unknown.
  - The feature could add an idle stop later: no event for N minutes counts as a limit (point H1 in `F0020-feature-1.md`).
- **The resume.** Each call gets its own `run_streaming` callback state (the sum per call). The run files are reused and removed only at the end. Both are plain to build.
- **Size.** About 100 lines and 13 criteria. Fine.

## Replacement texts

### E1 (recommended): the time-left clause, stated by reference to the Claude Code runtime

A child test cannot time a budget stop that leaves no time without being flaky: the stop would have to come after the limit's last moment but before the kill. The Claude Code runtime's matching branch has no test either (`tests/adapters/test_claude_runtime_resume.py` tests only a resume that runs out of time). So the story states the clause by reference, not as a rule that a criterion must pin.

In `## Interface`, replace

```text
within what is left of the request's time limit (none left: the resume is not started and the run ends `time_limit`), with the same run files,
```

with

```text
within what is left of the request's time limit, as the Claude Code runtime's resume does, with the same run files,
```
