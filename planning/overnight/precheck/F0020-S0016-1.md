  - `test_opencode_runtime.py:221`, the row `timed-out` of `test_the_state_directory_holds_no_file_after_a_run`, with `wait_seconds=30` (`WAIT_SECONDS` is 30);

  - as `Step(stdout=REPLY)`;
  - combined with another field (`Step(stdout=REPLY, exit_status=1)`, `test_opencode_runtime.py:219`);
  - as plain text (`Played(stdout=REPLY, ...)` of `tests/confine_support.py`, `test_opencode_runtime_launch.py:167`, and `pytest.param(REPLY, ...)`, `test_wiring_opencode.py:62`).

  The Interface's rule ("only as `Step(stdout=REPLY)`" or "combines the events with others") does not name the third way in so many words (optional edit 2).
- Today the nine modules collect 86 test ids: confinement 4, left-out tools 14, limit wait on stderr 5, provider limit 12, resumed words 2, runtime 23, runtime folders 2, runtime launch 14, wiring 10.
- The new test reads `tests/`, not `src/`, so `[tool.mutmut]` in `pyproject.toml` needs no deselect line, as for `tests/test_shared_test_helpers.py`. No structural test pins test module names beyond `tests/test_test_names.py` (no "protocol"). `docs/project-guide/agents.md:138` names the stand-in module but none of its constants, so criterion 4's "docs: none" holds.

**Prototype.** I wrote the following:

- `REPLY_EVENTS`, `REPLY = Step(stdout=REPLY_EVENTS)` and `WAITING` in the stand-in module;
- the nine modules importing them, each dropping its copy;
- `tests/test_opencode_shared_steps.py` in the style of `tests/test_shared_test_helpers.py`, one parametrized test with rows `reply` and `waiting` and texts split by `+`.

The results:

- Before the move, the new test failed both rows: `2 failed`.
- After it, `2 passed`. The nine modules with the new test and `tests/test_shared_test_helpers.py`: `93 passed`.
- The collected counts per module were the same before and after.
- Ruff found 32 `F401` (imports such as `text`, `result_text`, `step_finish`, `step_start` and `WAIT_SECONDS` no longer used), 3 `I001` and one line over 100 characters. All went with `ruff check --fix` and `ruff format`, after which both were clean. This is the tester's housekeeping, but it touches the import lines of every module (optional edit 2 names it).

**Smoke test.**

- On the prototype, blocks 1 and 2 each printed one line, `tests/adapters/opencode_stand_in.py`, and block 3 ended `2 passed in ...`.
- On today's code, block 1 lists nine files and block 2 three.
- Bytecode can break blocks 1 and 2. The split texts are joined with `+`, and Python folds constant strings when it compiles the module, so a `.pyc` of the new test holds the whole text. With bytecode written (`compileall`, `PYTHONDONTWRITEBYTECODE` unset), `grep -rlF` also listed `tests/__pycache__/test_opencode_shared_steps.cpython-312.pyc`. The image sets `PYTHONDONTWRITEBYTECODE=1`, and both runtimes pass it to the agent, so the smoke tester will not meet this. A human who runs the block in a host checkout that has `__pycache__` folders would (optional edit 4).
