## A. Can cause a bug or a wrong decision

### A1. A torn record line containing a multibyte character stops every check, though the comments say this cannot happen

- **Where:**
  - `src/factory/adapters/record_log_jsonl.py:26-30` (`read`) and `:33-39` (`_parse`)
  - `src/factory/application/known_results.py:63-69` (`_read`)
  - `src/factory/application/files.py:84-89` (the `RecordLog.read` docstring)
  - `src/factory/application/disk_records.py:47-51` (`last`, with no guard at all)
- **What:**
  - `JsonLinesRecordLog.read` decodes the whole file with `read_text(encoding="utf-8")`, then skips the lines that fail validation. Its own comment says that "a kill during a write can tear the last line".
  - If the tear falls inside a multibyte UTF-8 character, `read_text` raises `UnicodeDecodeError` before any line is parsed.
  - `UnicodeDecodeError` is a `ValueError`, not an `OSError`. So `KnownResults._read` ("Unreadable records only cost a run; they must never stop a check") does not catch it.
  - It leaves `KnownResults.run` as a `ValueError`, which the `run` docstring lists as a fault of the run. The dispatcher then counts an error for every stage that runs a check, on every work item, until a human repairs `/state/records/results.jsonl`.
  - `ResultRecord.last_line` is the last line of a project command's output (`known_results.py:39`), so a non-ASCII character there is ordinary: a tool's check mark, a quote, mutmut's emoji.
- **Not affected:** the stop records (`StopRecord`: event, scope, reason, time and instance) and the disk records are ASCII in practice.
- **Why it matters:**
  - Telemetry the factory treats as disposable can halt it.
  - It fails as error posts on every work item, not as a stop that names the file.
  - The `RecordLog.read` docstring ("A line that does not validate is skipped") promises the opposite.
- **Smallest fix:** in `JsonLinesRecordLog.read`:
  1. Read bytes.
  2. Split them on `b"\n"`.
  3. Decode each line on its own, and skip a line that does not decode, as `_parse` skips one that does not validate.

  Keep the docstring's promise. `KnownResults._read` and `DiskRecorder.last` then need no change.
- **Story:** coder and tester. Tests: a file whose last line ends in the middle of `é` reads as its whole lines; `KnownResults.run` reruns the command instead of raising.

### A2. The `Tick` docstring says nothing local is read; the tick reads two local files

- **Where:** `src/factory/application/tick.py:61-65`. Also `:93` (`run`'s docstring) against `:1` (the module's docstring).
- **What:**
  - The class docstring says: "The tick status is kept from one run to the next, and nothing local is read."
  - In fact the tick publishes the local stop records (`_publish_stop_records`, which calls `StopPublisher.publish`; `stops.py:137-138` reads `boundaries.stop_records`).
  - It also reads and writes the local health file through `StopService`, and the result records through the stage.
  - `run`'s docstring lists "Check the disk, fetch, load, restore, preflight, clean up, evaluate and dispatch" and leaves out the publication of the stop records, which the module docstring names.
- **Why it matters:** agents read docstrings as the design. "Nothing local is read" invites a coder to put local state into the tick, or to drop the publication as out of place. The real rule (`docs/decisions.md`, *The checkout is disposable...*) concerns the checkout, not the state directory.
- **Smallest fix:**
  - Class docstring: "the remote is the only truth for work items; the checkout is disposable. Only the instance's own state directory (health, stop records) is read locally."
  - Add "publish the stop records" to `run`'s docstring.
- **Story:** coder (docstrings only). Can join story S5 below.

### A3. The six optional `Boundaries` fields are a compatibility shim that switches safety features off silently

- **Where:**
  - `src/factory/application/boundaries.py:42-50`: the comment "Last and optional, so that every construction written before them stays valid" sits on `settings`, `disk`, `disk_records`, `stop_records`, `waiter` and `result_records`, each `| None = None`.
  - The production branches on `None`:
    - `tick.py:120-123`: no disk stop at all.
    - `known_results.py:27-29`: no result reuse.
    - `disk_records.py:26,48`
    - `stops.py:78,138`: stop events not recorded or published.
    - `costs.py:63-64`, `provider_limits.py:24`, `task.py:115`, `known_results.py:60`
- **What:**
  - Only one construction exists in `src` (`entry/wiring.py:255-286`), and it sets all six.
  - Only three exist in tests (`tests/conftest.py:189`, `tests/proof_support.py`, `tests/entry/test_wiring_boundaries.py`).
  - The constructions "written before" that the comment protects are gone.
  - What is left is a way to build `Boundaries` without the low-disk stop or the stop records, with nothing to show for it. The tests use the `None` values as "feature off" switches (`replace(boundaries, disk=..., disk_records=..., settings=...)` in `test_acceptance_facts_disk.py:51`, `test_disk_recorder.py:73` and others).
- **Why it matters:** a second entry point, or a change to `build_boundaries` that drops a field, type-checks and passes every test but the wiring test. Production then silently loses a stop. `CLAUDE.md` *Architecture* wants the wiring to pick the adapters, not to leave features off.
- **Smallest fix:**
  1. Make the six fields required.
  2. Give the `boundaries` fixture in `tests/conftest.py` real implementations under `tmp_path`, plus a disk stand-in with ample free space.
  3. Remove the `is None` branches.

  `settings` may need a test default (`local_settings`).
- **Story:** coder and tester. **Unsure** whether the gain is worth the fixture change: about 25 tests replace these fields. The human should weigh it under *Prefer solid over clever*. The low-cost alternative is a wiring test asserting that all six are set. Check whether `test_wiring_boundaries.py` already asserts it before choosing.

- **What:** `CLAUDE.md` *Architecture* (R5) says that what the runtimes share lies in `factory.adapters.agent_launch`. These pieces are shared logic that `make duplicates` does not report, because each block is shorter than pylint's threshold. The difference that has already appeared:

- **Story:** coder, with a tester row for whichever behaviour U1 settles on. No test of another story should need to change, except the state-missing row if U1 changes it.

### B2. The committed stop records file is written by the application layer, and its JSON Lines format exists twice

- **Where:**
  - `src/factory/application/stops.py:147-151`: `path.parent.mkdir(...)`, then `path.write_text(text + stop_records_text(missing), ...)`.
  - `src/factory/domain/stops.py:81-94`: `stop_records_text` and `parse_stop_records`.
  - `src/factory/adapters/record_log_jsonl.py:19-39`: the same format, for the local file.
- **What:** `CLAUDE.md` R13 asks for one reader and one writer class per format, and puts all file I/O behind adapters ("`factory.application` ... knows no concrete tool"). Here the application layer writes a file itself, and the stop-record line format has two codecs: the domain functions for `main`'s copy and `JsonLinesRecordLog` for the local copy. They agree today. A1's fix would change only one of them.
- **Why it matters:** this is the one direct `write_text` in `application` (`acceptance.py:125,417` only create folders). Fixing a decoding fault in one codec leaves the other unfixed.
- **Smallest fix:** add `RecordLog.render(records) -> str` and `RecordLog.parse(text) -> list[R]`, or a small `StopRecordsWriter.write(path, text)`, so that `StopPublisher` neither writes nor formats itself. Then drop `domain.stops.parse_stop_records` and `stop_records_text`, or keep them as the one codec that the adapter calls.
- **Story:** coder and tester. Low urgency. Do it together with A1 if it is cheap.
