## What could not run as written, and what stood in for it

1. **The recipe's `uv run` offline.** In the first run, the agent's `uv run` had no `UV_OFFLINE`, and it failed before installing. It tried to resolve the build backend from the network, although `hatchling` is in the copied cache: "Failed to resolve requirements from `build-system.requires`", "No solution found when resolving: `hatchling==1.32.4`", "Failed to fetch: `https://pypi.org/simple/hatchling/`", "dns error". The recipe text stays unchanged, so `UV_OFFLINE=1` was added to the agent's `env -i` environment only. No network was used. The instance itself has network, so it needs no such variable.
2. **pytest.** pytest, pytest-xdist and pytest-cov are not in the image's uv cache: it holds only the production dependencies, from `uv sync --no-dev`. So the small project declares a console script named `pytest`, a stub that prints its arguments and exits 0. The recipe's `uv run pytest ...` therefore ran the sync it always runs first, then the stub. It printed the recipe's full argument list and `test: green`. The sync before pytest is the step under test, and it is unchanged. What pytest itself writes (`.reports/`) was not exercised; the feature leaves that out of scope.
3. `sudo` printed "unable to resolve host <container id>: Temporary failure in name resolution", from `--network none`. It is harmless: the command ran.
