# F0051 eval: where the time and the tokens go

This file records, for the stories of F0051 (the repository is ordered by subject), where the time and the tokens went, measured from the cost records (`.costs.jsonl`) and the run transcripts in `session-logs/vm-f0051/`. It has one section per evaluated story, appended in the order the stories were evaluated; the first section also covers the last acceptance of F0050 (the factory shows what it runs and what it uses), which ran at the same time. Numbered items ("candidate 12") are those of `planning/f0051-candidates.md`; a finding marked "(new)" is not in that list. Dollar figures are the cost records' own. Splits of a cost by kind of token are estimates (the records do not carry a price list; a least-squares fit of the 25 records of these three work items gives about $25.5 per million output tokens, $0.22 per million cache-read tokens and $5.9 per million cache-creation tokens, with a worst error of $0.16 per run).

#### 1.2 What the dropped test changes cost

The first coder (`e5249aa7`, 455 s, $0.79, 28 turns) moved the 18 modules and rewrote every test import, moved the 60 test modules, changed the guards and the duplicates baseline, ran `make check` twice and ended with `review`. Its take kept `src/` only; the factory's gate was red at once (619 mypy errors in 399 files, entry 8, `check_red`, 8 s). The work went back through `doing` (relay) to `tests`.

Measured, from the stall (00:32:28) to the green gate (00:43:12):

- 3 runs, $0.94, 466 s of run time, 10.7 min of wall time: the relay coder `24c78741` ($0.25, 51 s, 9 turns; it read the 47 KB work item twice and ended `tests`), the tester `0c1842dc` ($0.39, 245 s, 17 turns; it did the rewrite again with a script and ran the changed tests, which were 470 modules, in 131 s), and the coder `4f351c06` ($0.30, 170 s; it changed nothing, ran `make check` for 138 s and the factory ran the same check again, 148 s).
- Of that, the tester's rewrite ($0.39, 4 min) would exist in any route. What the lost changes added is the relay coder ($0.25, 51 s) and the first coder's lost test work: of its 455 s, one of the two `make check` calls (about 140 s) and about 40 s of test edits and path fixes; I estimate $0.3 of its $0.79. Together about $0.55 to $0.85 (10 to 15 % of the story) and 5 to 9 minutes. If the second tester had not been needed at all (the first tester doing the rewrite, as feature decision 5 now says), the saving would also include the 245 s and $0.39 of the second tester's wait, but the same work would sit in the first tester's run, so the real saving is the $0.55 to $0.85 and not the whole $0.94.
- A second cost no one counted: the factory's stall paragraph (the "The factory left out changes outside the write paths" list) is 31.8 KB in the journal, 27 % of the final 119 KB work item, and every later role read it (new, finding 4 below).
- It also used one of the two stall attempts of `doing` (`attempts: 1`, "attempt 1 of 2"). A second red gate would have stopped the story.

Why it happened: the coder's R14 tells it to write only within its write paths "in the pipeline definition", and the pipeline definition gives it no `tests/*`. The coder never opened `pipeline.yml` in its first run; the relay run did (call 5, "I've confirmed that the coder's write paths exclude `tests/` and `security/`"). The intake accepted an Interface that needed `tests/` changes ("The leave of feature decision 5 covers every other change to tests") without saying who makes them, and decision 5 did not yet say that the tester does it in its first run. The human has since added that sentence to `feature.md` (decision 5, "S0001, 2026-11-05"). S0002 is the first story that shows whether it works; watch whether the first tester then writes the rewrite with a script, and whether its `lint` gate stays green (it does not run `make types`, which is red by design until the move).

#### 1.3 How the rewrite was done, and how to make a move cheaper

The coder used one generated `sed -E` expression over every file under `src` and `tests` that names `factory` (call 5, 18 modules, `\bfactory\.<layer>\.<name>\b` and `src/factory/<layer>/<name>.py` pairs), six one-line `sed` commands for the `from factory.<layer> import <name>` forms (10 files), a `python3` heredoc for the guard `_is_domain`, and `ruff check --fix` and `ruff format` to re-sort. 28 turns, 26 Bash calls, one denial (a compound `git add -A -n . ; git diff ...` refused). The tester `0c1842dc` wrote a Python script in a `mktemp -d` directory (406 files rewritten), then the same six `sed` forms by hand, then `git mv` of the 60 modules that the new test itself printed in its failure message (the test lists them: `pytest tests/test_areas.py | grep -oE "tests/(domain|application|adapters)/..."`, which is a neat way to get the list but a clumsy one). So the rewrite was written twice, by two roles, and each time the `from X import name` forms were found by grepping afterwards.

What would make the next six moves cheaper, in order of saving:

1. **One script that does the whole mechanical move from the table, run by the tester (tests) and the coder (source) in their own scopes.** The table `AREAS` in `tests/test_areas.py` already says every module's old and new place. A script `scripts/move_area.py <area>` (or `make move AREA=...`) would read it and: `git mv` the source modules, rewrite all four import forms (`import a.b`, `from a.b import c`, `from a import b`, dotted strings and `src/factory/...` path strings), `git mv` the test modules that qualify, and call `ruff --fix`/`format`. It is deterministic, so the review of the script replaces the review of 410 files (see finding 3), and the six hand-written `sed` forms disappear. Estimated saving per move: 15 to 25 turns of the tester or coder, about $0.3 to $0.5 and 3 to 4 minutes, and fewer misses. The script belongs in the first move story's Interface or as a small story before S0002 (it is new code, so it needs the human's leave: CLAUDE.md "new top-level"-style rule does not cover `scripts/`).
2. **A smaller check after a rewrite.** The tester's rule is to run the changed test files; after a move that is every test (470 modules, 131 s). `uv run mypy --strict src tests` (seconds) plus `pytest tests/test_areas.py` plus `pytest --collect-only -q` prove that every import resolves, and the coder's `make check` and the gate run the rest. Saves 130 s per move story (more where the tester's run would be the third suite on the same tree, as here).
3. **A smaller Interface does not help much; fewer rounds do.** The 18 modules took the coder 162 s of model time. The cost is in the rounds (reviewer $2.44, relay and recheck $0.94) and not in the module count. Splitting S0001 would add 6 runs' fixed start per piece ($0.5 or more) and not remove any round.
